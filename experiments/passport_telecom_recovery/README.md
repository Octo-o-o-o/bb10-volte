# Passport 电信重启恢复

本轮基线为 Cursor 已部署并在 Passport SQW100-4 上跑通的电信方案。先从手机完整备份 304 个文件，逐项核验原清单的 15 个载荷文件。原控制包装器 SHA-256 为 `e1206f67ca8a48100de53a68523c65c22448e0728b92bfcb1e12f627cf729eb7`，本轮仅更新该 Python 包装器，其余 14 项载荷包括原生模块、IMS 组件、软件加密驱动、配置请求和启动 shell 均保持原字节。

## 漏项与恢复顺序

原电信流程仍是 1,800 秒手动测试。到期后它按设计停止 IMS，恢复 DCA 来源及 UE0/voice0，并清除数据优先标记。电信既不在自动启动许可名单中，自动配置函数也没有接入电信的冷启动快速路径。因此手动测试成功不等于之后可以长期运行或在重启后自动恢复。

这次重启的现场状态为：SIM 归属 460-11，UE0，GSM/460-00 紧急服务，无自有 IMS；软件提供器已被正常重启清除。独立名称工作进程已在新开机周期运行，但它正确地没有给其他服务网络强行套用“中国电信”。名称补丁没有修改无线电或 IMS 参数。

先核对并归档已恢复的旧运行记录，重新保存四份 DCA 原文到电脑并核验散列，通过 Cursor 原来的 DCA 流程写入数据优先。机主再从电源菜单正常重启，让 Passport 基带重新读取 UE1。本轮没有把飞行模式当作基带冷启动。冷启动后已恢复 460-11 正常 LTE，名称进程自行恢复“中国电信”。

## 包装器改动

- 将电信基础配置加入“可凭实机回执授权”的自动启动范围，继续要求双向通话、双方声音、LTE 和完整 SIP 对话回执；不预先写入成功标志。
- 电信回执增加当前 SIM 指纹约束。自动配置前再次核对回执、持久化标记、DCA 备份计划及当前 SIM；同一运营商的另一张卡也不能沿用当前卡的回执。
- 自动管理器先将公共 prepare_connection 的最早电信调用接到 Passport 流程，再在配置阶段调用原来已经跑通的 `telecom_ensure_lte` 冷启动快速路径，并将 DCA 恢复计划写入本次 journal。底层连接、原生 IMS 补丁和 APN 配置保持原方案。
- 手动验证仍使用有期限的测试模式。人工验收后启用已有 AutoRoot v4 入口，正常重启后的正式管理器走原自动服务路径，不创建手动测试 deadline 或手动 watchdog。停止时仍按原有归属检查恢复配置并保留软件提供器到正常重启，不在线卸载提供器。

这套独立现场恢复只覆盖本机当前验收的电信卡。其他会话的通用换卡调度器和 Windows/Mac 程序整合是另一项工作，不在本轮直接改写。

## 验收

当前进度、配置散列和实际通话／重启结果见 [现场记录](../../materials/passport-telecom-recovery-2026-10-31.json)。在记录完成前，手动 IMS 注册不等于双向通话或自动重启验收通过。

```powershell
python -m unittest discover -s experiments/passport_telecom_recovery -p 'test_passport_*.py' -v
```

57 项检查包括原有提供器保留、未知进程和配置保护，以及电信自动启动、旧 lease 到期不影响自动管理器、同运营商换卡拒绝和 DCA 计划归属。真实重启和声音仍须以机主与现场信令为准。

第一轮自动尝试已触发，但遗漏公共函数的最早电信分支，进入原生 IMS 被动等待；在任何提供器／IMS 配置前由电脑停止，保留该轮未通过的记录。第二版补上该分支，并直接用公共 prepare_connection 的实际源码增加回归检查。第二版实机重启仍以现场记录为准。
