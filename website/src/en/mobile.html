RECOMMENDED / ROOT → BAR → SYSTEM INSTALLER

The native installation route after Root

A native app, registered by BB10. The BAR keeps a stable application and author identity for upgrades. Installing the icon does not activate or modify the radio service; backups and activation happen separately inside the app.

  1. Restart normally, unlock, and wait for the Root success notification.
  2. Obtain the BAR and SHA-256 from the same trusted release. Use an existing compatible BAR installer, or the matching desktop “More → Install phone app” assistant when that version is released.
  3. Wait for the system installation result and confirm the installed version. Then open BB10 VoLTE and follow the backup and activation steps.

The current public r15 desktop does not contain the new phone-app assistant. Installing a candidate or downloading a ZIP does not add that menu. Use a candidate only with its matching delivery instructions.

AutoRoot v4 documents unsigned BAR installation after its Root notification, plus local Root helpers and a package format. This app follows that native package approach. “Recommended” is this project’s guidance for the checked environment, not BlackBerry certification or proof that every Root method works. AutoRoot author’s documentation.

Computer-free daily use is established separately from computer-free first installation. Q20 and Passport installation evidence includes commands sent over trusted Root SSH to the phone’s installer; it does not establish a complete phone-only first-install flow.

01 / FIRST INSTALL

Which entry point is already on your phone?

Root means system administrator access. A Root marker, working SSH, a terminal icon and the ability to install a BAR are separate requirements. Confirm any first-use system installation or storage permission prompts normally on the phone.

A / INSTALLER ALREADY PRESENT

BARinstaller is already installed

Confirm it can actually install native BAR files with your current Root setup, and that a local Root execution helper works. Both are needed for installation and management entirely on the phone.

  1. After an official mobile release is published, obtain its BAR and verification information from the project Release.
  2. Verify the source and complete SHA-256 as instructed. Open the BAR with your existing BARinstaller and confirm system prompts.
  3. Check the actual installed version, then open BB10 VoLTE to check local Root access and device requirements.

If BARinstaller is not installed yet, it needs its own first-install entry point. Downloading a BAR alone does not provide one.

B / LOCAL TERMINAL ONLY

A working Root terminal is available

The terminal must actually execute Root commands on the phone. The release must also support its Python environment and system installation interface. An ordinary terminal or SSH available only from a computer is insufficient.

  1. Wait for an official Release to provide a mobile bootstrap for your Root setup.
  2. Save the matching bootstrap and BAR on the phone, then verify their source and checksums.
  3. Use only that release's documented local command. Check the same installation job and the actual app version.

The candidate bootstrap is still under hardware testing. Do not combine scripts from different releases or execute web content directly as Root commands.

C / ONE-TIME DESKTOP ASSISTANCE

Rooted, without a local installer

Use the matching new desktop “More → Install phone app” assistant: connect and unlock one phone, check its identity, select the exact BAR, then confirm installation. The assistant verifies the complete package, system receipt and installed files.

Public r15 does not have this menu. The new assistant remains a candidate while Q10 installation is tested. If a result is unknown, inspect the same task instead of submitting it again.

Trusted desktop connection and recovery

D / NOT ROOTED YET

Complete separate Root preparation first

The mobile app is not a Root tool. It cannot directly grant an unrooted phone permission to install apps or modify the system.

Back up personal data, then choose the desktop first-Root process for the exact hardware variant. Flashing erases data and requires separate explicit confirmation. Never use firmware for a different model.

Read first-Root requirements and tested scope

Verify installation through the actual version

In candidate testing, AutoRoot installer could still print completed after a 120-second timeout. Without a matching SUD success result, and with the registered app version unchanged, this is not an installation success.

Keep the original job and check its system installation result and actual app version against the target. A completion message, icon or working older version alone does not prove the new version is installed. Do not repeatedly submit an installation when its result is unknown.

02 / BACK UP, ENABLE, CHECK

After installation, follow four steps

This describes the candidate workflow. Keep your SIM, number and system dialer; your carrier's plan still applies. The SIM needs VoLTE provisioning and normal LTE data service.

  1. Check the phone and choose a backup location

    Open the app and confirm the model, OS, current SIM and check results. Choose an SD card or internal storage. Originals are saved and read back for verification before changes are allowed.

  2. Choose “Activate VoLTE” and wait for the current task

    Read and confirm the operation. Submitted work continues in the phone's background; closing the app does not cancel it. Reopening queries the same task. Do not reinstall.

  3. Restart normally when prompted

    Restart from the power menu and unlock. Wait for the system Root success notification, then open the app once. Do not repeatedly tap an unresponsive icon; the waiting page cannot run if the OS refuses launch. Checks run automatically inside the app. Passport network policy changes may require another restart.

  4. Test outgoing calls, incoming calls, audio and LTE yourself

    Call out with the system dialer, then receive a call from another phone. Keep each connected for at least two minutes, then make one more outgoing call. Confirm audio in both directions and LTE / 4G throughout, then record the result. The app does not dial for you; IMS registration alone does not establish working calls.

A call record applies only to the current SIM, boot and payload version. Power off before changing SIMs. Recheck after a SIM change, restart or version change. Test SMS, number display and long standby separately too.

03 / KEEP THE ORIGINALS

Where should backups go?

SD card: prefer an available separate copy
A mounted card that passes write and readback checks can hold original backups. Keep it inserted until installation finishes. Afterward, keep another copy elsewhere if possible.
Internal storage: usable, but still on the same phone
Internal storage is available without an SD card. It helps local restoration but does not protect against loss of the phone, storage failure or files becoming inaccessible when the OS cannot start. You can export to an SD card later.
Use the exact export location shown in the app
Internal exports are under /accounts/1000/shared/documents/BB10-VoLTE/; SD card exports are under /accounts/1000/removable/sdcard/BB10-VoLTE/. Each task has its own subdirectory. Keep original backups and receipts. A redacted diagnostic report cannot replace original backups.

04 / UPDATES & RESTORATION

Update, disable or restore

Payload updates and app BAR upgrades are separate

The candidate's update check and offline ZIP import update runtime components and adaptation payloads. The publisher's signature is verified. If an online check fails, use a trusted offline package from the corresponding release. Bundled installation payloads and offline packages need no online download; registration and calls still require the carrier network.

Upgrading the interface app itself uses a new BAR with the same application identity. Follow the Release requirements, replace it through an existing installation entry point and verify the actual app version. A completed ZIP update does not mean the BAR was upgraded.

Finish restoration before removing the app

Use disable and restore, rollback or full uninstall from management. Restart normally and continue the same task when prompted. Uninstall can require staged restarts; removed files do not prove restoration has been verified. Deleting the home-screen icon alone does not restore service configuration or remove Root.

If a task is interrupted, files are unknown or backups conflict, keep the original task and files. Recheck or export a report first. Restoration requires ownership and verification evidence; repeated installation is not a way to overwrite unknown state.

Mobile and the new desktop manager use management protocol 2. Old r14 / r15 / r16 desktop clients cannot fully manage the new payload; use a newer manager matching the phone service protocol. If an older client is rejected, upgrade it and follow the release's disable, restore and normal-restart adoption steps.
