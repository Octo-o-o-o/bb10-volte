Complete user guide · Latest release

From download to real-call verification

Complete preparation, connection, preflight checks, installation, and call tests in order. “Registration passed” does not mean calls work: use the system dialer to test incoming and outgoing calls, and confirm clear audio in both directions.

A few terms: root means administrator access to the phone; preflight means checks before installation; IMS registration means connecting to your carrier’s calling service. The English interface shown on this website previews the current source; older release packages may still display Chinese.

01 / 09

Back up and check the requirements

Check the exact hardware variant and OS in Settings → About. The validated scope is SQN100-3, SQC100-2 and SQW100-4 on OS 10.3.3.3216. Connect one charged phone.

Do this: Download the correct desktop package and verify SHA-256. Windows needs 10/11 x64; first Root preparation on Mac needs macOS 14+. Back up the phone before any wipe and allow at least 15 GB on the computer.

You should see: The app shows Connect phone and Automatic carrier selection. A phone with working Root can skip first flashing.
Stuck at this step?

An older OS needs the System upgrade route and about 24 GB. Never use firmware for a different model. Check the USB cable and drivers if Windows does not detect the phone.

02 / 09

Connect the phone and choose your route

Connect and unlock the phone using a data-capable USB cable, then select Connect phone. Enable development mode when the first development connection requires it.

Do this: Choose the whole old flashing folder if you have it. If Root works but files are missing, choose Authorize again from the phone. Use the first Root route only after checking the phone status.

You should see: The app identifies the model, USB network and verified Root status. A failed connection does not prove that Root is absent.
Stuck at this step?

Recover the original material or authorize again for an authentication failure. With existing AutoRoot, open BlackBerry World once if the connection service has not started.

03 / 09

First Root: obtain the matching firmware

Open First use and connection help → First Root and check the detected model. The example uses SQC100-2; other models must use their own firmware.

Do this: Use Download matching firmware or the browser download links. Keep the complete original file without running or extracting it, select it, then choose Verify and import firmware.

You should see: The app confirms that stock firmware was imported and verified. Personal Root images have not yet been prepared.
Stuck at this step?

Try the alternate source after a download interruption. For an import failure, check the exact model and complete file. Never bypass verification.

How to save feedback

04 / 09

Prepare personal images, then confirm flashing

After firmware import, scroll down and choose Prepare Root images automatically. The app still needs tools, personal connection material, image construction and verification.

Do this: Only after the images are ready, verify the model and backup, acknowledge the data wipe, select Start Root flashing, and read the second confirmation. Keep USB stable and follow the window prompts.

You should see: Flashing becomes available only when image preparation, model matching and the wipe acknowledgement are complete.
Stuck at this step?

Read the reason above a disabled button. Export feedback after a build failure and retain the prepared materials for investigation.

How to save feedback

05 / 09

Finish phone setup and verify Root again

After flashing, complete setup on the phone and open BlackBerry World once as required by the Root method. Return to Connection check. A store network error does not itself mean Root failed.

Do this: Select Detect again. Continue only when USB, SSH and effective Root verification have completed.

You should see: The exact model, target OS and effective Root are verified. Returning Root users join the same flow here.
Stuck at this step?

Unlock a newly rebooted phone and wait for its services. For an identity mismatch, check trusted materials for this phone instead of bypassing verification.

How to save feedback

06 / 09

Check, back up and install carrier adaptation

Open Automatic carrier selection and select Check device. Verify the phone, SIM and carrier. Use an active VoLTE-enabled USIM with working LTE data.

Do this: When checks allow installation, select Back up and install automatic adaptation. Wait for backup verification, installation and read-back, and retain the computer backup.

You should see: The app confirms the backup and installation and explains the reboot. If it asks you to enable adaptation first, do so.
Stuck at this step?

After interruption or an unknown state, check the device before retrying installation. Follow the explicit stop, restore and reboot sequence for an older payload.

How to save feedback

07 / 09

Reboot normally and check the current boot

Use the normal reboot option in the phone power menu. Unlock it after startup and wait about 3–5 minutes with USB connected.

Do this: Select I have rebooted, check again. Recheck the connection first if USB has not recovered.

You should see: The app verifies this boot’s SIM selection, IMS registration and LTE. Passport may need another normal reboot when entering or leaving the Telecom attachment policy.
Stuck at this step?

A 4G icon is not registration verification. Airplane mode is not a normal reboot. Follow the current stage guidance rather than reflashing or reinstalling.

How to save feedback

08 / 09

Disconnect USB and test real calls

After current-boot registration succeeds, verify real calls on the phone. Registration and successful calls are separate checks.

Do this: Disconnect USB. Make an outgoing native-dialer call, then have another phone call back. Wait until the connected-call timer reaches 00:35 before hanging up. Check audio both ways, LTE and number/carrier display.

You should see: Incoming and outgoing calls work with two-way audio and LTE. For later SIM changes, shut down normally first.
Stuck at this step?

Preserve the state after network search, emergency-only service or a failed first call. Record the step and export feedback rather than repeatedly calling, installing or rebooting.

How to save feedback

09 / 09

When stuck, save useful feedback

Select Need help / Feedback on the current page. Add a short description of the step and expected result. The entry remains available during an operation.

Do this: Refresh and review the preview, then save the ZIP. Check its contents and send the whole file through your usual contact channel or to octoooo@octoooo.com. The app sends nothing automatically.

You should see: The ZIP includes the step, version, recent timeline, failure codes, permitted check results and available redacted build-failure excerpts. A successful retry does not immediately erase the earlier failure.
Stuck at this step?

History covers the last 5 sessions with this feature, up to 400 entries each. It cannot recover earlier-version logs and excludes private directories, keys, phone backups and raw SIP logs.

Preparation and risks

Check the exact hardware variant under Settings → About. Automatic carrier support covers rooted Q10 SQN100-3, Q20 SQC100-2 and Passport (Q30) SQW100-4 on OS 10.3.3.3216, with matching native file hashes.

  • China Mobile 460-00, Unicom 460-01 and Telecom 460-11 USIM, without ISIM; the plan must provide VoLTE and working LTE data.
  • A reliable USB data cable, personal Root SSH key and verified host key are required for the initial installation.
  • Windows 10/11 x64; Mac: macOS 11+ on Apple Silicon or macOS 10.15+ on Intel. No separate Python installation is needed. r14 passed native first Root and restart autostart on Apple Silicon Mac/Q20; Intel hardware has not been tested.
  • Back up the phone. Initial Root preparation for Q10, Q20 and Passport needs about 15 GB; a stock OS upgrade needs about 24 GB. The app selects firmware for the exact model. Flashing erases data. r14 passed native first Root on Windows/Passport and Apple Silicon Mac/Q20. Full first-use GUI operation, Q10 first Root, Intel flashing and old-OS upgrades remain unverified. Never flash firmware for another model.
  • Long-term standby, roaming, other regions and emergency calls have not been comprehensively validated.

02 · Download and launch

Launch on Windows / macOS

Windows

Windows 10 / 11 · 64-bit (x64). Windows 7, 8 / 8.1 and 32-bit systems are not supported.

  1. Download the current bb10-volte-0.5.0-r20-windows-x64.exe and its matching .exe.sha256 file from the release.
  2. Follow the SHA-256 verification steps below before opening the EXE. Python, Tcl/Tk, SSH/SCP, carrier templates, and phone-side payloads are included.
  3. This is a single-file portable app. It extracts into the system temporary directory at launch and cleans up after a normal exit. Launching and everyday use do not require administrator rights; first-time USB driver installation shows a separate Windows UAC prompt.

Signing status: The current Windows EXE has no Authenticode signature, so Windows may show “Unknown publisher.” Download only from the project's releases and confirm the complete SHA-256 matches. Do not run it if verification fails.

macOS

Apple Silicon macOS 11+ · Intel macOS 10.15+. Initial Root preparation requires macOS 14 or later.

  1. Download the current bb10-volte-0.5.0-r20-macos-universal.dmg and matching .dmg.sha256 file, then verify SHA-256 first.
  2. Open the DMG, drag bb10-volte.app into Applications, and launch it from Applications. No separate Python, Tk, or OpenSSH installation is needed; the app uses the SSH/SCP included with macOS.
  3. Connect and unlock the phone using a USB data cable, and allow the accessory connection when prompted by your Mac. If USB networking is unavailable, check “Connect to Mac” under Settings → Storage and Access → USB Connections on the phone.

Signing and verification scope: The current Mac package is Universal, signed, and notarized. “Universal” means it contains Apple Silicon and Intel architectures, not that every Mac or Intel model has been tested on hardware. Minimum OS versions were checked against the release package; older macOS versions and Intel hardware remain untested.

Initial Root support can differ between releases. For an unrooted phone, follow the first-run documentation for your downloaded version and actual model. A new interface in later source code does not mean an older package supports it.

Once the app and phone service are prepared, they can run while the computer is offline. Initial Root or driver preparation downloads missing materials only after you explicitly enter and confirm that process. IMS registration and real calls always require the carrier network.

03 · Establish a trusted connection

Connect your phone

  1. Establish USB networking first. Connect and unlock the phone using a data cable. Charging or a visible storage drive does not mean USB networking is ready. If the status does not update after reconnecting, click to check again. Do not preinstall old BlackBerry Link software, change IP addresses arbitrarily, or weaken host-key checking.
  2. Click “Connect phone” on the main screen. The app finds and actively verifies saved personal connections; the connection profile field can be left empty. Both the old q10-root and current bb10-root aliases are recognized. Custom settings are under More → Advanced connection settings.
  3. Open “Connection help” if needed. You can select the entire folder from a previous flash so the app can identify the single set of login materials inside. Confirm their source before creating a local profile. Keep private keys in a protected personal directory; never send them to an issue or group chat.
  4. Check the connection result. Confirm the model, hardware variant, OS, Root, and existing service status. Reopening the app only rechecks the last successfully connected phone; it does not automatically install or flash anything. Development mode, SSH, Root, and IMS are separate layers. With valid Root SSH, development mode does not need to stay enabled.

r14 enables SMS correlation: Q20/Unicom and Passport/Mobile passed short, two-part and independent identical-text messages, with no duplicate delivery over at least three minutes. Bidirectional audio and LTE passed. Other SMS combinations remain untested.

Choose a recovery method for your phone's current state

  • Rooted, with your own connection files: Import your own ssh_config and ensure its referenced login private key and trusted known_hosts exist. Absolute Windows paths cannot be reused unchanged on a Mac; use the app's connection-recovery process to recreate the required setup.
  • Rooted, without the old computer's files: Use an existing, working Root terminal on the phone to authorize this computer independently. Follow the exact numbered steps shown by the app to transfer the public script and results, and enter PAIR only after your personal confirmation. This persistently appends an SSH public key on the phone. The private key always stays on the computer.
  • No materials and no working Root terminal: A direct connection is not possible. A connection failure alone does not prove the phone is unrooted. Check Root and SSH first; do not reflash as a speculative fix.
  • Host fingerprint mismatch: Check the trusted materials originally used for that phone. Do not disable strict host checking or assume a changed fingerprint means a damaged key.

First-time preparation for a confirmed unrooted Q10, Q20 or Passport

  1. Open first-time preparation in Connect phone / Connection help. Check USB networking. If Windows drivers are missing, the wizard downloads and verifies pinned materials, then installs through UAC after your confirmation.
  2. Open “Initial Root,” check the exact detected or selected hardware variant, and reconfirm your backup and about 15 GB of free space.
  3. Click “Automatically prepare Root image.” The app downloads and verifies pinned tools and firmware for that exact model, then generates personal keys and an image unique to this phone. Preparing the image does not flash the phone.
  4. Start flashing only after reconfirming the backup and actual model and explicitly agreeing to erase the data. If an unknown exit, interruption, or undocumented error occurs, stop immediately and preserve the current state. Do not retry blindly.
  5. Complete the required setup after first boot and activate Root using the original Root method (which may involve opening BlackBerry World once). Then return to the app and verify effective UID 0. Successful Root does not mean VoLTE or calls have passed.

r14 first Root passed on Windows/Passport SQW100-4 and Apple Silicon Mac/Q20 SQC100-2, followed by new-key Root and normal-restart autostart. Full first-use GUI operation, Q10 first Root and Intel USB flashing remain unverified.

For an older OS, open System upgrade and separately confirm erasing and writing model-matched stock firmware. Read back OS 10.3.3.3216 after boot before separately confirming Root. Unknown or newer OS versions are blocked. Supported rooted phones can use Automatic carrier setup directly.

Install once, then change SIMs offline

  1. Connect and unlock one rooted supported phone. Open Automatic carriers and confirm the exact model and current SIM.
  2. Choose Back up and install automatic carriers. The program verifies and saves original network settings, startup entries and the old payload before writing the new version, then verifies the files read back from the phone.
  3. Restart from the phone power menu, unlock, and allow around 3–5 minutes. Click Restarted — check again. The program checks the current boot, SIM, native IMS process, registration and LTE before showing success.
  4. If Passport says another normal restart is needed, wait for the policy write to finish, then restart normally once more. Airplane mode is not a substitute. The screen explains the reason and retains the recheck button.
  5. If USB disconnects, reconnect and recheck the connection. Reopening the app resumes from the actual phone state; it does not require reinstalling. If an update left autostart disabled, enable it first.

Future SIM changes: no computer required

Power the phone off normally, change the SIM, then start and unlock it. The phone selects the carrier. When Passport enters or leaves the Telecom attach policy, allow around five minutes for startup, then perform one additional normal restart. Hot swapping is outside the tested process.

Supported models, OS, native hashes, backup receipts and idle-call state are checked. Unknown state or conflicting external changes stop writes. The automatic-carrier workflow does not perform first-time Root flashing.

Real call acceptance

  1. Wait for current-boot registration, then unplug USB.
  2. Use the system dialer to call out, then receive a call from another working phone. For each, wait until the connected-call timer reaches at least 00:35 before hanging up.
  3. Check first-attempt connection, both audio directions, LTE throughout, your own number and the carrier name.
  4. Test after normal restart and powered-off SIM changes without reconnecting to a computer. For Q10, include about 20 minutes of LTE standby before calls.
  5. If searching for network, emergency-only service or a first-call failure appears, preserve the state and export a redacted report; avoid repeated redialing, reinstalling or restarting.

All nine model/carrier combinations passed functional acceptance. Six cases include phone-only SIM changes; the three initial-card baselines are recorded separately. Some phone ring logs rotated, so owner-confirmed duration and audio are distinguished from complete retained SIP timing. Q10 Telecom acceptance uses the last successful pair; first-attempt success was not assessed because earlier attempts had peer-number issues.

Disable, restore or update

  1. End all calls and keep USB connected. Open Automatic carriers and use its stop/restore action.
  2. The program stops its manager, restores owned settings from verified backups and checks the result. Restart normally to clear old runtime components.
  3. For a recognized older payload, install the new version after that restart, verify it, enable automatic startup and restart normally to launch it. Follow an additional Passport carrier-restart prompt if needed.

Keep original backups and update receipts. Restoration does not remove Root or reflash firmware. Unknown files, missing receipts or conflicting changes stop the operation; inspect state before retrying an interrupted write.

07 · Before running

SHA-256 verification commands

Download the package and matching .sha256 file from the same release. These commands assume the package is in your user's Downloads folder. If it is elsewhere, replace the path with its actual full path.

The command outputs a 64-character hexadecimal digest. It must match every character of the SHA-256 in the release's matching checksum file (hexadecimal letter case does not matter). Do not compare only the first few characters. If it differs, the files came from different sources, or you cannot confirm the match, do not run the package. Delete it and download it again from the release.

08 · Preserve evidence and seek help safely

Troubleshooting and redacted reports

Cannot connect to the phone

Check unlocking, data cable, USB mode, USB networking, SSH, and Root in order. Charging alone proves nothing about the connection. On Mac, check “Connect to Mac”; on Windows, let the first-time wizard handle drivers. If a host fingerprint changes, verify trusted materials first rather than disabling security checks.

Preflight fails or mobile data does not work

Read the failed item's reason and advice. Check the SIM, LTE, actual MCC/MNC, data APN, and factory configuration. If mobile data does not work normally, do not bypass installation requirements. A non-default configuration is not automatically a damaged one.

Registration pending confirmation

Preserve the current state, check status later, and confirm carrier service. The end of the default 180-second observation window does not mean installation automatically succeeded and must not trigger repeated reinstallation. This device passes only when every real-call checklist item passes.

Installation interrupted or state unknown

Keep installation records and error messages, rerun preflight, check status, then contact the maintainer. Do not delete transaction records, force an overwrite, or Root the phone again. Do not publicly upload private installation records.

Export and inspect a redacted JSON report

  1. Connect the phone and run a fresh check so the report reflects its current state. Open More → Export check report and save the JSON to a location you choose. The tool does not upload reports automatically.
  2. The report keeps only allowlisted checks, results, and necessary model, OS, MCC/MNC, and similar information. It excludes full IMSI, IMEI, ICCID, PIN, phone numbers, SSH keys, host addresses, raw configuration contents, and raw SIP logs.
  3. Open and inspect it yourself before sharing. Check custom names and additional text for personal information. Do not additionally upload the private directory, private keys, ssh_config, known_hosts, private installation records, or raw communications logs.
  4. When submitting a report to the project's GitHub Issues, include Latest release, Windows EXE or macOS DMG, computer OS, phone model and variant, full BB10 OS version, carrier and region of use, roaming or number-porting status, failed stage, and error message. For working results, also report each incoming-call, outgoing-call, two-way-audio, continuous-4G, USB-disconnected, and post-reboot result.
