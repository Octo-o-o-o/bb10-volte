# 已 Root 手机的连接恢复

[English](RECOVER-CONNECTION.en.md) · [首次使用](FIRST-RUN.md)

Windows 和 Mac 均可打开 **首次使用 → 连接检查 → 已 Root 但没有连接配置？恢复连接**。此功能不要求先知道用户刷了哪个包，不刷机、不清空手机数据。程序按用户现有材料和实际连接结果推进；不能仅凭 Root 提示、Term49 图标或开发模式判定 SSH 已可用。

## 有连接材料

- 本机有完整且有效的 `ssh_config`：使用“导入已有连接”，或将配置留空并点击“检查设备”查找已保存的材料。配置引用的密钥和可信主机记录也必须在本机可读。Windows 的 `C:\…` 路径不能直接用于 Mac；跨电脑取回本人材料后，可用下一项补建本机路径。
- 只有登录私钥：进入“有登录私钥”，选择私钥及手机的 RSA 主机公钥 `ssh_host_rsa_key.pub`，也可使用包含 `169.254.0.1` RSA 记录的可信 `known_hosts`。核对来源和指纹后，程序复制私钥到受保护的个人目录，补建配置并验证 Root。原文件不改动。
- PuTTY `.ppk` 需要先用 PuTTYgen 导出 OpenSSH 私钥。当前导入流程支持无口令 RSA 私钥；带口令的密钥不会通过命令行传递口令。也可走下面的新授权流程。

手机的 `ssh_host_rsa_key` 是服务端私钥，不能当作电脑登录私钥。没有可信手机主机公钥时，使用手机端授权结果；程序不会通过关闭主机校验来连接。

## 没有连接文件

此路径不需要旧 Windows 电脑或文件，但要求手机上已有能取得有效 UID 0 的 Root 终端，例如原 Root 包提供的 Term49 与 `__root` / `u_root`，以及脚本支持的既有 SSH 配置。电脑不能替用户绕过手机权限；仅有终端图标或开启开发模式还不够。

1. 点击“生成并导出授权文件”。应用在本电脑的个人目录生成独立 RSA 密钥；导出的 `bb10-pair-编号.py` 只含公钥与固定脚本。把此脚本复制到手机内部存储 Downloads。不要复制或发送电脑的 `identity` 私钥。
2. 在手机终端按应用显示的命令进入已有 Root shell、检查 UID、授权这一脚本的路径并运行它。命令使用 `/accounts/1000/shared/downloads/`，如果文件放在其他位置，需要按实际位置处理；建议按向导放入内部 Downloads。
3. 脚本确认有效 Root、既有 SSH 配置和授权文件的布局后，输入 `PAIR`。它先保留原文件的备份，再追加本电脑公钥，保留所有原授权并避免重复添加。不改手机私钥、Root 固件、通话配置或开机标志。
4. 脚本生成同编号的 `bb10-pair-编号-result.json`，只包含本电脑公钥、手机主机公钥及配对状态。若 SSH 尚未运行，可单独输入 `START` 启动已有 SSH 服务并限定 USB 地址；已有 SSH 无需重复启动。此步骤不保证重启后仍开启 SSH，持久启动需使用原 Root 工具。
5. 把结果复制回生成脚本的同一台电脑，点击“导入手机授权结果”。应用检查编号与本电脑公钥，要求确认结果来源，随后固定手机身份并验证 SSH 有效 UID 0。只有成功后才记住连接并允许返回主界面。

关闭程序不会删除待配对密钥；重新打开后可以直接导入同编号结果。不同电脑分别生成自己的授权，不能拿另一台电脑的结果替代。已有手机身份记录不会被不同结果静默覆盖。

## Mac 没有旧文件时，如何传递授权脚本与结果

USB 网络未建立或 Mac 无法浏览手机内部存储时，可使用已有可读写的 microSD 卡、相应 Mac 读卡器，以及手机文件管理器。此方案不依赖旧 BlackBerry Link，也不要求 Finder 直接挂载手机内部存储；不要为此格式化或清空卡。

1. 在这台 Mac 的“恢复连接 → 没有连接文件”生成并导出 `bb10-pair-编号.py` 到卡。只传这个公开脚本，Mac 内部的 `identity` 私钥保留原处。
2. 在 Mac 安全推出卡，放回手机。用手机文件管理器从媒体卡将脚本复制到**设备内部存储的 Downloads**，保持文件名与编号不变。
3. 打开手机已有有效 Root 终端，按应用显示的内部 Downloads 精确路径授权并运行脚本。脚本自行检查有效 UID 0；权限不足会在写授权前停止。本人决定允许**持久追加此 Mac 的 SSH 公钥**后，才输入 `PAIR`。它备份授权文件并保留旧密钥，不修改固件或通话配置。
4. 若确需临时开启已有 SSH，可另选 `START`；已有 SSH 无需重复启动。新授权不会自动安装 Root 或创建通用 SSH 配置，遇到不支持的布局会停止。
5. 结果固定写到手机内部 Downloads 的 `bb10-pair-编号-result.json`。用手机文件管理器将它复制到卡，安全取出，再通过读卡器导入**原来生成请求的同一台 Mac**。确认结果来自当前手机，再由应用固定主机身份并严格验证 SSH/有效 UID 0。

这只解决公开文件传递；随后仍要有可用 USB 网络。不同电脑独立授权，不能借用另一台电脑的结果。没有读卡器/可用卡时，需要另一条本人可用的文件传递途径；没有材料、没有有效 Root 终端时必须先用原有 Root 工具恢复访问。

本轮 Mac 验收复用了本人已有连接材料，没有实际执行这套卡传文件、`PAIR` 持久写入或 `START` 流程；不能将其列为全新 Mac 一键授权实机通过。已发布 r5 的 Root 检测已知问题与仓库源码修复范围见[Mac 指南](MACOS.md#当前发布包与验证范围)。

## 不能自动解决的情况

- 手机没有有效 Root 终端，也没有任何可用登录材料：需要先在原 Root 工具中恢复访问，向导不会承诺“无权限也能连接”。
- 自定义 SSH 端口、非 USB 地址、非 RSA 主机密钥、条件配置或不同授权目录：保留原有配置走手动导入；新授权脚本会停止，不猜测路径。
- 本轮的恢复脚本仅完成目录模拟、密钥与桌面测试；未在第三方 Root 手机实写验收。不可把桌面测试当作所有一键 Root 包兼容承诺。
