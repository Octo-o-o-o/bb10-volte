# 手机 0.1.0.12 / 桌面 r18：一次集中人工验收

当前 v12/r18 修复手机新安装时私有 umask 导致 runtime 目录不可遍历的问题。新建与更新路径均先验证归属和内容，再明确设置运行目录权限；备份、状态与管理目录仍为私有。修复的实机 IMS、完整重装与通话/短信验收尚未完成。另有一次完整卸载后、重新安装前的唤醒内核/watchdog 重启，根因未确定；仍阻止发布，不能由短时未复现或权限修复替代解决。

当前候选**尚未公开发布**。v10 已安装并核对注册版本，Passport 移动卡在 r17 策略重启后已完成三次各至少两分钟的双向/重复通话，机主确认声音与全程 4G 正常。v10 Windows 756 项测试通过；各版本、最终 Mac 发行物及其余人工结果见[验收记录](MOBILE-VALIDATION.md)和同版候选回执，不能由构建或 IMS 注册替代实机验收。

v11 已安装并核验 SUD success 与注册版本。它修复 v10 在英文检查过程中切换中文时残留英文状态/按钮的问题，并补齐阶段和错误提示；无线载荷保持 r17。最终中文真机结果及后续生命周期操作请写入绑定本次哈希的独立验收回执。

本清单不用重跑坏签名、ZIP 上限、QNX 锁释放等自动探针。重点是实际安装版本、系统权限、现有任务续接和用户能看到的完整操作。各项写“通过 / 未通过 / 未测”，不要用旧版本记录填新版本结果。

第一、二轮针对三个基线机型的**自动协议 2**流程。旧实验路线的 23 选项与恢复范围见下方独立段落，不把自动原件导出回执或完整卸载承诺套到 trial。

## 先确认本轮起点

- 目标包：手机 **0.1.0.12**、桌面 **0.5.0-r18**，管理协议 **2**；核对同一次候选交付的 SHA256SUMS 与产物回读报告。
- 当前真机：Passport SQW100-4、OS 10.3.3.3216、AutoRoot v4。四份原件已导出手机并在电脑核对哈希；不要删除或公开这些原件。
- v8 已验证首页、管理页、重启后不按 Check 自动完成旧停用任务和内置 r16→r17 更新。这些是历史验收。当前 v11 完整重装暴露运行目录权限错误；服务已停用恢复，准备 v12/r18 修复验收。已有任务先按当前记录续接，不重发历史操作。
- 发生过接通约 36 秒后掉话并仅限紧急通话；已保存日志、停用恢复并正常重启。当前原件保留，后续策略候选需重新完成驻网、较长双向通话与短信验收。
- 先正常解锁，按原 Root 方案等待本机入口恢复。若还不能检查原状态，停在此步排查；不要反复重启、重新 Root 或刷机。SSH 未返回不能单独证明本机 Root 失效。

## 另行验收：受控实验路线

实验页应有旧 4 配置与 19 个精确后缀配置，共 23 项；其中 13 组可进入受控手动试测，6 组 Passport 只读。逐项核对名称与准确硬件，不用通用配置替代其他后缀。没有对应实机时只能记为选项/准入检查，不能填写通话通过。

- [ ] 切换 profile 清除旧准入，每次开始都重新检查已装 profile 与当前兼容条件；只读项不出现写操作。
- [ ] 普通 13 试测的说明明确：无电信附着修改，恢复以启动时 PPS journal 为准，不宣称自动协议 2 原件导出回执。
- [ ] 停止实验适配会关闭旧自启动并等待恢复。更新前必须先停用恢复且无悬挂 install-transaction；中断记录保留，拒绝盲重试。
- [ ] “卸载实验启动项”保留私有载荷与备份，不能显示为自动协议 2 的完整移除；没有新增 legacy rollback。
- [ ] 导出的试测记录带 last_checked_not_live，用户可分辨上次检查与实时状态。语音/SMS仍须在每个真实组合上独立验收。

## 记录与发布判断

每组结果只公开日期、候选版本、准确型号/OS/Root 方案、运营商名称、操作阶段、通过/未通过/未测和必要的脱敏错误码。不要附个人操作 ID、私有路径、密钥、SIM 身份、电话号码、原始回执或通信日志。

未测项目保留“未测”，不能写“手机版全部通过”。最终 v12 / r18 全量检查、包回读以及上面准备发布范围内的实机项目完成后，才发布同一组字节。后续人工结果可作为绑定同一哈希的独立验收附件，避免为补录结果改变已验证字节；源码内的已知结果见[MOBILE-VALIDATION](MOBILE-VALIDATION.md)及[公开设备证据](../materials/mobile-device-validation-2026-11-02.json)。

原厂未 Root 手机仍走电脑首次 Root；本清单不提供纯手机从零 Root，也不要求修改安全设置、代替用户接受系统权限或绕过锁屏。

启动前边界：Root 生效前反复点图标已在本机触发 Launcher 权限拒绝与 Navigator 循环等待，随后黑屏；不要用这种方式测试应用内 Root 等待。仅在系统已允许应用进程启动后验证 helper 延迟，不得改系统门禁或强行制造 Root 失败。
