# 激活可靠性、前台恢复与后台等待

2026-11-08：本地候选 desktop r36 / mobile 0.1.0.37，preview `idle1108`。优先顺序：保持通话服务、明确需要处理时引导用户、减少无意义的后台工作。未安装到手机，未发布；不能把旧版通话验收或主机测试当成本候选的实机功耗和通话结果。

## 正常使用

手机界面、短期配置任务、常驻通话服务是不同的进程。手机界面进入后台或锁屏就停止轮询；每次进入前台最多请求亮屏十分钟。配置任务保存结果后退出。真正提供 IMS 注册和系统拨号器通话的原生进程继续运行；关闭手机界面、退出电脑版或断开 USB 不会要求它退出。

管理器保留当前开机的所有权、恢复和换卡判断。直接退出管理器既会丢失这些能力，也会使现有两端的存活核验不通过。该候选保留管理器，但降低稳定时的工作量：

| 情况 | 管理器行为 |
| --- | --- |
| 开始注册 | 保留每 3 秒观察，连续 60 秒确认 IMS、200 OK、LTE 和无线电 ON 后结束快速观察 |
| 稳定连接 | 用只读 PPS 订阅等待相关状态变化；等待期间每隔 30 秒核对停止、进程退出和 SIM 保护条件，变化时提前唤醒；每 5 分钟做一次完整检查和日志/资源归属收集 |
| 已连接后暂时掉网 | 交由原生 IMS 自身处理；管理器仅短期观察 60 秒，随后回到等待；不再次配置或拉起 IMS |
| 长时间等待注册、无线电关闭或状态不明 | 初始快速观察最多 120 秒，之后同样降低频率；不会永远每 3 秒扫描日志 |
| 事件订阅不支持、失效、EOF 或反复报告相同值 | 关闭这组观察描述符，回退到每 30 秒观察；不重启或恢复 IMS |
| 手动停用或确定换卡后的停止 | 仍走已有受保护的恢复流程；等待状态每 30 秒观察一次停止条件，仍在原 180 秒恢复预算内 |

事件过滤只关心 IMS、无线电及 SIM 的相关字段。打开方式只读，不创建或发布 PPS 对象；关闭管理器时释放描述符。采用 full mode 避免为每个事件累积 delta 队列。机制依据 [QNX PPS 6.5 架构说明](https://qnx.com/developers/docs/6.5.0SP1.update/com.qnx.doc.neutrino_sys_arch/pps.html)及 [QNX 文件描述符等待说明](https://get.qnx.com/developers/docs/7.0.0/com.qnx.doc.pps.developer/topic/subscribe_notification_filedescriptor.html)。实际 BB10 过滤/通知行为仍需实机确认，回退路径保留。

状态文件仅在状态变化或文件缺失时写入，不再定时刷写相同心跳。辅助显示结果也只在内容变化时保存。两端的“已连接”继续读取当前开机、管理器/原生进程、SIM 和实时系统状态，不把旧状态文件的时间戳当作存活凭证。

## 不把未知状态当成停止依据

旧版在 SIM 信息连续缺失 30 秒后可停止服务；监控、日志或状态保存异常也可能进入配置恢复分支。本候选移除这两类误判路径：

- SIM 暂时未就绪、锁定、身份字段冲突或读取失败，均保持正在运行的 IMS。等待多久都不会因此推断换卡。
- 只有旧卡摘要有效、新卡 READY 身份有效且不同、再次读取一致、两次确认通话空闲，才考虑换卡处理。提醒发送后还会再次核对卡和通话空闲，避免通知期间开始通话后继续停止。
- 监控读取、日志采集、辅助显示或状态文件保存失败，不停止、重启或重新配置正在运行的原生 IMS。
- 首次配置失败仍保留已有恢复逻辑；显式停用、真实换卡、正常关机和原生 IMS 自身退出仍分别处理。这不承诺运营商或无线电永不掉网。

## 提醒与手动继续

同次开机的确定换卡提醒引导正常重启；换卡重启后提示打开应用查看当前状态。手机和桌面均提供明确的换卡步骤：正常重启并解锁 → 手动检查状态 → 按本次检查结果继续。它们不会把“检查状态”变成重新安装、重复启用或自动重启。

现有克制通知门槛保留：已知配置失败并恢复、明确恢复未完成、明确需要重启以及确定的任务结果才可能通知；暂时无信号、读取失败、短信忙、单独非 200 注册回应、退出是否属于关机不明等仍保持静默。未知不会被显示为已激活。通知不强制把界面拉到前台，不因回执不明反复发送。

LTE-only 默认值、停用后恢复精确原网络模式的入口、已有设备准入和每次开机一次原生启动限制保持原有候选行为。换卡后的正常开机会按当前卡执行必要的初始化；需要额外重启时由明确状态引导。

## 普通重启和卸载

同一 SIM 普通重启仍须运行必要的启动步骤：当前实现依赖开机后重建的临时原生进程、运行配置及软件加密提供者。跳过这些步骤不能保证通话可用。无需为此打开界面，完成后进入低频等待。

仅通过系统删除手机应用图标/BAR，不等于应用内部的“完整停用并卸载”。服务和开机入口安装在应用沙盒外；按现有代码布局，删除界面不会主动移除它们。但本次未进行“删除 BAR → 正常重启 → 通话”的实机验收，不把这个推断当成已验证保证。保留界面便于接收后的检查、诊断和恢复；若只想减少后台开销，关闭界面即可。应用内部完整卸载会恢复配置、移除服务与入口，不能保留本方案提供的激活。

## 验证边界

主机测试覆盖：稳定/丢网/未知状态、长时间等待、PPS 事件唤醒与超时、EOF/订阅失败/相同值风暴、时钟回拨、日志和磁盘写入失败、明确和不明确的换卡、通话期间延后停止、两端手动引导、原有通知与升级门禁。测试使用虚拟时钟、真实 POSIX 管道或隔离夹具，不读写手机。

QNX 编译、签名包验证、Windows 离线自检及两端实际制品的后台文件逐一比较单独记录。实机待验：事件等待是否生效、锁屏后连续呼入呼出与声音、待机跨网络变化、换卡与恢复、正常开机、LTE-only 短信/数据、真实通知以及同条件的电量/CPU/内存对照。数值功耗和“完全不占资源”均没有证据。
