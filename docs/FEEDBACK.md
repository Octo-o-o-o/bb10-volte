# 问题反馈（待随下一版桌面应用发布）

每个主要步骤底部都有 **遇到问题 / 反馈** 和 **查看本步图文教程**。连接、驱动、首次 Root、系统升级、三网安装、重启检查、通话验收和恢复时均可打开反馈；操作进行中也可使用。

1. 点击反馈，补充卡住的位置和原本希望看到的结果。
2. 查看脱敏后的预览，再点 **保存反馈包**。也可以复制简短摘要。
3. 检查 ZIP 后，通过原联系渠道或 `octoooo@octoooo.com` 发给开发者。应用不会自动上传或发送。

反馈包包含 `feedback.json`、`timeline.txt`、`README.txt`：当前步骤、桌面版本及平台、近期操作顺序、失败代码、允许导出的检查结果、候选型号绑定和六个原生文件的校验摘要、当前状态文字，以及可获得的 Root 构建失败摘录。成功重试不会覆盖此前错误。日志在事件发生时保存；重启应用后仍可带入之前的会话。

历史只覆盖安装此功能后的最近 5 个有记录的应用会话，每个会话最多 400 条，超出时标记 `truncated`。它不是全部历史日志归档，不能追溯旧版本未记录的错误。磁盘无法写入时会提示，并允许导出本次内存记录。

记录先按字段白名单筛选和脱敏，再写入应用私有目录的 `feedback/`。导出不遍历整个私有目录，不包含 SSH 配置、私钥、密码、号码、手机备份、原始 SIP 或手机通信日志。异常定位只记录类型及代码文件名/行号，不记录局部变量。Root 构建仅提取本次已知 `root-build.log` 尾部的失败行并脱敏。自由填写的说明仍请自行检查；不要填写密码或号码。

本版优先提供可离线保存的反馈包：无需账号或反馈服务器，失败时不依赖网络，也让用户决定分享哪些内容。未来若增加云端收件，应在预览之后另设明确的发送操作，并给出接收位置和结果。

r15 已包含反馈入口，官网图文和视频展示对应操作。旧 r14 未包含新反馈入口时，使用 **更多 → 导出检查报告**，并补充出错步骤；旧报告主要是当时的检查快照。

实现与验证见 [feedback.py](../tools/feedback.py)、[feedback_gui.py](../tools/feedback_gui.py) 和 [test_feedback.py](../tests/test_feedback.py)。视频与重录方法见 [首次使用录制说明](recordings/FIRST-USE-RECORDING.md)。
