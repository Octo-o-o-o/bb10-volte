# 电脑磁盘占用与手动清理

**手动清理适用于 r42 及后续版本；r43 EXE / DMG 已包含下方自动复用和清理改动。**

## 保存位置

| 使用方式 | 个人材料根目录 | 下载缓存 |
| --- | --- | --- |
| Windows EXE | `%LOCALAPPDATA%\bb10-volte\private` | `%LOCALAPPDATA%\bb10-volte\private\downloads` |
| macOS 应用 | `~/Library/Application Support/bb10-volte/private` | `~/Library/Application Support/bb10-volte/private/downloads` |
| 源码运行 | 项目目录下的 `private/` | 项目目录下的 `downloads/` |

Windows 按 **Win + R**，粘贴路径后回车即可打开，以 `%LOCALAPPDATA%` 实际展开的位置为准。Mac 在 Finder 按 **Shift + Command + G**，粘贴路径。

## 可以删除哪些内容

先关闭所有 bb10-volte 程序、驱动安装窗口和刷写窗口。**正在刷机、刷写中断、手机还没有正常开机或结果不明时，保留 Root 和升级材料，先处理恢复。**

如果能确认**只是电脑端下载、解包或构建失败，从未开始手机刷写**，可以删除该失败包的 `stock`、`images`、`stock-upgrade` 子目录后重新准备，同样保留根目录的密钥和日志。无法确认是否已刷写时，按上面的恢复要求保留材料。

以下路径均相对于上表的个人材料根目录；表中 Root 包的完成条件之外，也适用上述“确认从未开始刷写”的失败准备情况：

| 路径 | 删除条件及影响 |
| --- | --- |
| `downloads/` | 下载缓存，可删除内容或整个子目录。包括固件压缩包、工具包、`.partial`、旧 `.invalid-*` 和 `.importing`；以后需要时会重新下载，未完成的下载进度会丢失。源码用户的缓存位置见上表。 |
| `root-kit/stock/`、`root-kit-*/stock/` | 解包后的原厂固件。手机已正常启动、Root 和连接已确认，不需要继续升级或恢复时可删；再次准备需要重新解包。 |
| `root-kit/images/`、`root-kit-*/images/` | Root 镜像与构建中间文件，通常是占用最大的部分。适用上述相同条件；删除后不能继续使用这份镜像刷写。 |
| `root-kit/stock-upgrade/`、`root-kit-*/stock-upgrade/` | Mac 升级用的签名分区，同样只在升级、Root、开机和连接均完成且无需恢复后删除。 |
| `windows-usb/`、`windows-usb-*` | 解包的驱动安装材料。驱动安装已结束且不需要排查安装日志时可删；不会卸载已装入 Windows 的驱动。后续重新安装需要重新准备。 |

`root-kit-*` 和 `windows-usb-*` 中的 `*` 表示随机后缀，例如 `root-kit-a1b2c3d4e5f6`。**请打开这些目录，仅按上表删除对应子目录，不要照着通配符批量删除整个 Root 包。**

**必须保留** `q10_root_rsa`、`q10_host_rsa` 及各自 `.pub`、`ssh_config`、`known_hosts`、连接配置、原始备份、`setup-state.json`、`firmware-upgrade.json`、构建/刷写日志和其他记录。不要删除整个 `private` 或 `root-kit*`，也不要靠删除 `root-flash.lock` 解除未确认的刷写状态。这些文件体积很小，丢失密钥可能导致电脑无法再连接已 Root 的手机。

Windows 单文件 EXE 运行时还会解包到 `%TEMP%\_MEI...`，正常退出会自动清理。异常退出可能残留；`_MEI` 也被其他软件使用，不能一概删除。只处理已确认属于 bb10-volte 且所有相关进程已退出的目录，例如其中 `project.json` 的 `name` 是 `bb10-volte`。浏览器下载的固件、重复 EXE/DMG 则保存在用户自行选择的位置，常见为系统“下载”文件夹，不在程序缓存的自动管理范围内。

## 后续源码的改动

- 重复准备前，核对完整型号、平台、配方、两份成品镜像、原厂固件及个人密钥；一致时复用已有目录，复用检查先于新构建的剩余空间要求。完整且配方一致的旧记录也能接续；无法证明匹配的旧包不自动删除。已开始刷写、已刷写或状态不明的记录不重置。
- 同一材料目录只允许一个准备任务；下载和导入继续使用文件锁。崩溃后锁由系统释放。
- 失败的新构建清理本次的 `stock`、`images`、`autoroot` 大文件，保留根目录中的密钥、连接文件和失败日志。下次准备也检查带本程序管理标记的中断构建；旧版无标记目录留给用户按上表清理。
- 成功后删除已校验完的分区中间文件，保留原厂固件和两份成品镜像。典型 Q10 旧包仅中间文件就约 9 GB；实际释放量随型号而变，不代表新构建不需要临时空间。
- 已有完整固件时，重复导入只校验，不再生成完整导入副本。导入/下载成功后清理对应文件的冗余续传进度；失败校验只保留小型记录，不再积累多份损坏固件。可继续使用的下载进度仍保留。
- Windows Q20 原厂 EXE 与缓存相同且文件系统支持时使用硬链接，共享一份数据；不支持则复制。删除一个名称不影响另一个，空间在最后一个硬链接删除后才释放。
- 驱动准备先校验并复用已有安装材料；新准备的失败输出和成功后的解包中间文件会清理。安装时仍执行原有散列与签名检查。
- “首次使用与连接帮助”和“手机系统升级”新增“存储位置与磁盘清理”，显示本机实际目录。

这些是电脑端离线准备改动，不代表新增手机实测或改变任何型号、运营商的验收结果。
