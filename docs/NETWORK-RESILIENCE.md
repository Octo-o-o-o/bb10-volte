# 开机等网、LTE 模式与手动选网

[English](NETWORK-RESILIENCE.en.md) · [三网适配](AUTO-CARRIERS.md)

本文描述 **r48 之后的未发布源码改动**，不表示已下载的 r48／手机版 0.1.0.48 包含这些功能。既有发行文件和 macOS r43 封板包保持不变。单台 Classic 的排障反馈是设计输入，不是所有型号、地区或运营商的新版验收。

## 默认行为

- 保持系统自动选网，兼容用户在系统设置选择的 MANUAL 模式。后台不会因为等网超时而擅自锁定某个 PLMN。
- 先给系统已有 LTE 搜网过程一个短暂窗口，再使用既有 LTE-only 激活策略。系统将射频值从 16 改成 19 等合法值后，启动准备流程可以协调状态，原始恢复记录仍保留。
- 前置等网超过原有窗口后，后台继续只读监听 PPS 网络变化，以最多 30 秒的周期兜底观察停止请求。未启动原生 IMS 时也可使用监听；事件能力不可用时采用有界等待，不声明零耗电。
- 网络等待期间释放管理锁，允许检查状态或停用。显式停用恢复工具管理的配置和选网状态；正常关机时不强行重载无线策略。
- 真正进入原生配置前才提交本次开机的原生启动令牌。前置失败且配置恢复完整、同卡、无原生 IMS／活动 VPN／加密提供器时，界面显示“重试连接”。已进入原生配置、换卡或 Passport 入网策略要求重启时，仍须正常重启；不能手工删除令牌绕过。

LTE-only 不提供 2G/3G 回落。持续无 LTE 覆盖时应查看网络设置，必要时停用并恢复，不能把“后台正在等待”当作通话已可用。

## 可选的归属运营商 LTE 选网辅助

高级入口在桌面 JSON CLI 中；手机上也可以使用系统原有手动选网。工具辅助必须显式执行，不会由开机等待自动触发：

```bash
python tools/ai_skill.py volte probe
python tools/ai_skill.py volte lock-network
python tools/ai_skill.py volte status
python tools/ai_skill.py volte unlock-network
```

需要安装与当前源码匹配的后台，并通过完整型号、OS、Root、原生文件、SIM 与恢复备份检查。必须移动网络开启、通话空闲、无原生 IMS／VPN，且加密提供器未使用；资源在用时拒绝操作，不结束现有 IMS。

目标优先采用现场已驻留的同运营商 PLMN，否则使用辅助候选：移动 `460-00`、联通 `460-01`、电信 `460-11`。不会直接把新号段 USIM 的 HPLMN 当成必定广播的基站网络。这些目标不保证适合每个共享网络或地区；无效果时恢复 AUTO，或使用系统手动选择实际可用网络。

工具只接管原为 AUTO 的选网状态。用户已设置 MANUAL 时返回 `system_manual_selection_preserved`，保留原设置；驻留网络不能可靠证明原先选择的目标，所以不猜测恢复值。

先保存恢复记录，发送 `scan_mode` 后读回实际状态，再以字符串 MCC/MNC 和整数 RAT 发送 `network_select`。回执不等于驻网、注册或通话。失败时尝试恢复 AUTO；恢复不确定或无线关闭时保留记录并返回错误。显式解除、停用及下一次识别换卡时清理本工具的锁定记录。

## USB 与诊断

单个 BlackBerry USB 设备的 `/30` 对端变化时，桌面连接可复用现有 SSH 身份和严格主机密钥校验。必须是同一条 link-local `/30` 的手机与电脑地址；多设备、其他远程主机或代理配置不会被猜测改写。

不会改写旧 Root 密钥的 `from=` 来源限制、扩展 SSH 监听地址或关闭主机密钥校验。旧授权若仅接受固定来源，发现动态对端后仍可能认证失败；应核对原授权或使用既有配对流程，而不是重新刷机或忽略密钥冲突。

HTTP 发现可用但 SSH 拒绝时，先解锁并等待 Root 服务；这不证明未 Root，也不证明锁屏是唯一原因。

诊断显示 AUTO/MANUAL、漫游设置、LTE 频段位图及解码列表，不导出小区标识或 SIM 身份。漫游标志、频段能力及 IMS 200 OK 不能代替数据、双向通话、声音和短信验收。新卡首次注册可能需数分钟，不要因短暂 `connecting` 重复启用或连续重启。
