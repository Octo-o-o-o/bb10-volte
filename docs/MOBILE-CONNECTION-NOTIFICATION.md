# VoLTE 连接通知（本地候选）

后台统一服务在每次开机首次确认当前 SIM 的 VoLTE 注册后，发送一条 BlackBerry Hub 通知，并显示简短的系统轻提示“VoLTE 已连接”。应用无需保持打开。Hub 保留中英文详细说明；屏幕上的提示独立收起，不等待用户看到或点击。

触发条件与手机版连接状态一致：服务启用、管理器和本项目原生 IMS 进程存活、本次开机状态、当前开机选择及 SIM 一致、运行阶段为 running、IMS connected、REGISTER 200 OK、IMS RAN 为 LTE 且无线网络为 lte。安装完成、Root 就绪、旧缓存或单独的 REGISTER 200 均不会触发通知。这不增加任何机型或运营商支持，也不代替通话、声音、短信、数据和正常重启验收。

通知尝试先记入手机私有 `state/connection-notification.json`，同一次开机只尝试一次。刷新页面、网络短暂重连、管理器重新读取状态不会重复弹窗；下次正常开机重新满足条件后可以再次提醒。通知与 Root 提示共用系统通道 `sys.service`，为 Hub 使用独立的 `bb10volte_…_hub` 条目 ID，轻提示由单独的原生 Toast 窗口显示，标题明确标注 VoLTE；不会修改或清除 Root 通知。它不发送短信、邮件或 BBM，也不写入手机号、SIM 身份或原始通信内容。

0.1.0.24 候选使用 `/pps/system/notify/control` 的现有 `uib` 类型保存 Hub 记录，并通过 BB10 BPS `dialog_create_toast` 在屏幕底部显示“VoLTE 已连接”和“关闭”按钮。`dialog_set_cancel_required(false)` 使点击按钮立即关闭。原生 Toast 与 Hub 完全独立，不使用持续停留的 `alertuib`，也不修改系统通知设置。

带按钮的系统 Toast 默认计时可能等待首次触屏，所以辅助进程另设最多 15 次、每次 100 毫秒的事件等待；匹配当前 Toast 的用户响应立即结束等待，无人操作也在约 1.5 秒请求 `dialog_cancel`，为系统在 2 秒内收起留出余量。正常及异常出口均销毁自己创建的窗口；不等待解锁或用户看到提示。没有向通知服务发送 Cancel/Delete，不会清除 Hub 或其他系统通知。

收起请求结果独立记录为 `popup_dismissal`，API 返回错误不能记作接受成功。接口接受请求不等于用户实际看到了界面。Hub 或 Toast 失败互不影响，也不触发 IMS 停用、恢复或重启；整个辅助进程上限仍为 5 秒。

安装新 BAR 只更新界面和内置组件。已经安装的后台服务还需通过现有“更新手机服务”流程更新，按界面要求停用、恢复及正常重启后，才会运行新通知逻辑。旧服务不会仅因安装新图标而拥有此功能。

本地自动检查覆盖未注册不通知、SIM/开机/进程边界、每次开机去重、Hub/轻提示独立 ID、简短文案、系统拒绝、请求 ID 匹配、短写入、回执丢失时仍限时收起、异常清理及 Hub 保留。

2026-11-06，在 SQW100-1 / OS 10.3.3.3216 上发送明确标注“通知测试”的独立临时探针，系统返回 `res::notify / dat::ok`；机主确认弹窗与 Hub 通知均可见。测试没有更新、停用或重启正在运行的通话服务。手机版候选包中的自动触发、关闭应用后的日常运行、下一次正常开机和其他型号仍待分别验收。详见[通知验证记录](../materials/mobile-connection-notification-validation-2026-11-06.json)。

同日后续轻提示实验：PPS 静音 Toast 在约 1356 毫秒发出取消请求，1357 毫秒收到成功回执；机主确认无需点击即可在约 2 秒内消失，Hub 通知仍保留。随后原生带按钮 Toast 的实机显示请求返回成功，约 1519 毫秒请求关闭并返回成功。点击关闭已由真实控制流的模拟响应测试覆盖，实机点击观察尚待机主反馈。两种临时探针均已清理，正在运行的手机服务未修改。旧 0.1.0.23 候选保留，后续使用 0.1.0.24 候选。
