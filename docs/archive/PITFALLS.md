# 排查与踩坑独立归档

这些内容用于理解证据和避免重复试错。正式操作顺序在 [安装指南](../INSTALL.md)。

| 尝试 / 误判 | 现场结果 | 后续结论 |
| --- | --- | --- |
| Alt+右Shift+H、设置页输入escr | 打开Assistant或无反应 | 旧平台入口不能假定适用于这台BB10 |
| 浏览器地址栏、网页链接打开escreen:// | 搜索引擎跳转或“无法打开”toast | 不再依赖工程屏入口完成本方案 |
| Sachesi USB连接 | 持续搜索 | 改用实际可工作的Root/USB网络/SSH链路 |
| AppWorld一直loading | Term49出现，后续root SSH可用 | Root触发与商店联网成功是不同条件 |
| Term49 pidin无权限 | `/tmp/root.done`存在 | 普通应用终端权限不等于root SSH权限；用有效UID核实 |
| 已有4G和短信，所以IMS应正常 | `ims`映射到普通3gnet | 4G数据、IMS专用PDN、IMS注册、实际语音分别验收 |
| 照搬另一台安卓的IMS参数 | 对照能读IPv6/P-CSCF/MMTEL | 参数由Q10本机网络和SIM取得，不复制其他设备身份、密钥、MBN |
| 先启动IMS还是先建立APN | 两种顺序仍无有效路由 | 核心障碍是平台/接口选择配置，不是单纯先后顺序 |
| IMS_always_on 网络列表 | 本机解析器实际是布尔文本 | 类型猜测无效；后续数组方案离线拒绝 |
| 创建IPsec SA返回22就猜密钥长度错 | NULL算法原生实现存在，软件提供器却被禁用 | 读算法范围与提供器状态；恢复原软件提供器后本机合成测试和实际注册通过 |
| PPS写语音偏好3就认为已生效 | EFS仍00 | 原生API20字节按值调用才得到03；PPS/API/NV枚举不同 |
| LTE Voice Support=true就是VoLTE支持 | 独立IMS Voice Support=false | 分清NAS两个字段；查询与通知的TLV编号也不同 |
| REGISTER200就是电话成功 | 第一轮拨号发生在限时窗口结束后；第二轮在线仍失败 | 每轮实际截止时间和PID必须记录，SIP事务必须区分 |
| 在线但双向拨号失败 | 来电被本机domain selection拒488；呼出转CS报NO_SRV | 在隔离副本的普通语音VoPS分支做精确修正后，出现真实IMS通话 |
| 读取整份slog不筛选实例 | 混入以前进程的注册与错误 | 只使用当前拥有的PID与本次时刻 |
| 长窗口只在末尾取一次日志 | 最早VPN创建记录被覆盖，停止时还出现新profile | 持续保留归属证据，停止后再采一次，并使用该子进程stdout补证 |
| 清理遇到未知VPN仍继续删 | 原实现保守拒绝删除，算法提供器保持开启 | 仅删除证据充分的自有UID；不能为“清理干净”移除未知对象 |
| SSH退出等同手机任务结束 | 拔USB使电脑连接reset，手机上的测试仍存活 | 核对手机进程与独立恢复机制；长期服务需明确自己的生命周期 |
| 命令重启后USB通就算已开机 | 曾停在BlackBerry Logo，用户一次电源键复位后回到桌面 | USB响应、桌面、4G与SSH分别核实，不能反复盲刷 |
| bb10mt原包可直接在Windows运行 | 缺libusb、LZO、OpenSSL DLL | 固定依赖来源/版本/架构；LZO需相应DLL名称 |
| 等待子进程退出后才读取PIPE | QNX的pidin输出填满小管道，安装预检超时 | 改用私有临时文件承接输出，保留超时；在网络配置修改前已拦住 |
| 只信任Python文件，未信任入口shell | 执行run.sh报Operation not permitted | 安装时逐个pathtrust载荷及addon入口；电脑控制入口也明确检查 |
| root Python直接使用-c | BB10明确禁用euid0的-c入口 | 把审阅后的诊断存成文件，再按Root环境的pathtrust流程执行 |
| 安装时pathtrust就认为重启后也够用 | Root日志证明addon入口被运行，但它调用的run.sh未重新获信任 | addon每次在Root就绪后显式信任下一层入口，再启动服务 |
| IMS进程先退出就立即恢复网络 | QNX关机可能先终止IMS；此时carrier也在重载，自动恢复发生冲突 | 非显式stop的原生退出保留账本；下次启动核对，避免关机途中再重载基带 |
| PPS对象存在就认为属性也保留 | 重启后自建对象还在，但非持久属性已消失，读到空对象 | 用安装账本确认自有对象，允许空对象重新写入或恢复；有未知字段时仍停止 |
| PowerShell 5.1继承了另一版本的模块路径 | Authenticode自动导入模块失败 | 签名脚本从当前PSHOME显式加载自身模块；5.1和7分别验证 |
| 对文件和目录递归套同一组OI/CI继承权限 | 归档目录内部分文件变成空ACL，无法读取 | 仅在私有目录根设置继承权限，子项正常继承；已恢复并逐个验证224个私有文件可读 |

## 已发生过的恢复

一次试验暂时令网络变为仅限紧急呼叫。恢复原配置并由用户复位后，桌面和联通4G恢复，随后独立核验原XML、PPS和APN状态。没有因此另刷未知固件。

另一轮因长日志覆盖而保留了两个自有VPN。首次补救在证据不全时停止，未修改设备；补齐同一进程的晚期日志和stdout证据后，删除自有profile并恢复算法提供器。这个失败成为当前所有权校验和停止后补采的依据。

这些事件的原始日志、原始配置、失败版本和完整检查点保存在原实验的私有档案中。公开目录保留结论、触发条件、解决方向；有效安装代码单独维护，避免用户误跑已废弃的实验。

## 应用清理后的启动超时（2026-10-27 夜间）

0.1.0 在等待系统 IMS 退出后，没有再次检查几分钟前取得的网络就绪结果。独立 IMS APN 在 45 秒内未连接便进入恢复并退出；桌面仍显示 4G 不能证明服务仍在运行。现场曾看到恢复期间蜂窝管理器报告重复加载 internet，PPS 中缺少互联网和 IMS 条目。单次重新加载原厂 XML 没有修复，正常重启后恢复；没有回装应用，也没有重刷固件。现有证据不能确定应用卸载导致该故障。

0.3.1 补上退出等待后的网络复查、最多三轮 IMS APN 等待和当前启动的状态标记。重试只等待原生 AlwaysOn 连接恢复，继续检查身份和配置所有权，不重复重置基带。额外的边界用例覆盖了 SIM 更换、LTE 丢失、配置被其他程序修改和主动停止。

另发现 BB10 缺少 shell `rmdir`，使成功预检后留下空的暂存目录。新的清理器使用 Python 3.2 逐项删除已核对的本次文件，再删除空目录；旧目录及内容不明的目录不批量清理。

加固版已在正常重启后自行注册，并通过系统拨号器双向短通话和双方声音验收；208 个采样保持 LTE / IMS connected。Root 就绪到注册约 4 分 42 秒，不能把“Root 成功”提示当成已经可以拨号。实际时长、原始证据范围及仍未测试的项目见 [验收记录](../VALIDATION.md)；记录器结束不影响常驻服务。
