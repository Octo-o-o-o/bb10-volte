# r14 评审与实机验收

基线为 r13／983fea1。本轮复核 11 个来源工作区；新增 675fbe3 的 SQC100-4 回传核对说明已合入，其余来源与集成历史或先前审阅快照一致。保留其他工作区的未提交内容。本记录为当前会话的代码评审与实际验证，不冒称独立评审。

修复重点与证据：

- Windows 首刷结果判定原先过宽、末尾提示缓冲、重复阶段可能先启动再检查。现要求真实完整写入与后续完成证据，先独占阶段日志；AutoRoot v4 的已知退出 73 仅限 OS 阶段。Passport 原版恢复、Root OS／radio 和新密钥 UID 0 已实测。
- 首次启动的 USB DHCP 地址不能固定为 169.254.0.1。发现仅访问唯一 BlackBerry USB /30 对端；Mac 使用限时、限大小且绑定接口的系统 HTTP 客户端。Q20 原版系统实际机型和版本已读回。
- Mac 上游 loader 资源损坏及写完后多余重连分别导致 CRC 错误和失败退出。修复固定输入哈希、完整签名 loader 提取和精确原生分支；不放宽完成判定。16 组 ARM64／Intel 函数仿真、Q20 ARM64 实际 radio 与两阶段 Root 通过；Intel Rosetta 只做原生启动，不宣称 Intel USB 刷写。
- 新刷 AutoRoot v4 可以没有 addons 目录；预检保持只读，激活时创建，拒绝文件或符号链接占位。Mac 共享用户刷写锁，密码在原生终端输入且不记录；Root-v2 诊断使用专用临时目录并限定清理文件。
- 首个短信候选新增 LOAD 头导致 QNX 加载器崩溃，已恢复为原有两个 LOAD。保留原 RX／RW 关系及原通话指令路径。最终运行镜像与两台实机读取文件逐字节一致；语音比较构造结果仍与旧版一致，正式服务显式启用短信 ACK 关联。
- 升级清单按真实 canonical JSON（包括末尾换行）计算，识别 r13、过程候选与实际已安装的短信候选；未知载荷仍拒绝。未引入自动重发或按短信正文去重。

Q20 SQC100-2／联通 460-01 与 Passport SQW100-4／移动 460-00 在 OS 10.3.3.3216 上通过原生短短信、两段长短信、两条同内容独立消息、至少 180 秒无额外投递观察和正常菜单重启自动启动。两端原生计数均为 captured 5／correlated 5，失败计数为零，日志开关恢复无冲突。两次短通话具备完整 SIP 接通／挂断，机主确认双向声音和 LTE 正常。详见[实机进度与失败记录](SMS-ROOT-ACCEPTANCE-2026-11-01.md)和[脱敏证据散列](../materials/sms-device-validation-2026-11-01.json)。

Windows 本轮 624 项回归中 622 通过、2 项按平台／权限跳过；未改动的符号链接测试已有管理员补测通过。官网静态 16 项、浏览器 21 项通过，覆盖中英文、窄屏、离线下载和无 JavaScript。原生短信验证覆盖九种策略、三个装载基址的 27 组调用点检查。最终 Mac 全套回归、包自检、签名公证、源码冻结和远端下载校验由随包 release-validation.json 记录。
