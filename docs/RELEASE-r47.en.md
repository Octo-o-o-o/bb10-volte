# Desktop r47 / mobile 0.1.0.47: Full three-carrier HPLMN coverage & stock XML fallback + Passport Telecom incoming-audio regression fix

2026-11-15. macOS remains at **v0.5.0-r43**. This release has no new Mac package.

- **Fixes newer Mobile / Unicom / Telecom USIM ranges failing activation with “no matching template”**: Expands HPLMN admission across all commercial three-carrier ranges — China Mobile `460-00` / `02` / `04` / `07` / `08`, China Unicom `460-01` / `06` / `09`, and China Telecom `460-03` / `05` / `11` / `12` — and adds case-insensitive APN matching for `cmnet`/`cmwap`, `3gnet`/`wonet`/`uninet`, and `ctnet`/`ctlte`.
- **SHA-256-pinned stock read-only carrier XML fallback & two-phase empty-APN bootstrap**: Because BB10 `10.3.3.3216` predates newer HPLMNs such as `460-08` (newer China Mobile 5G USIMs), `460-09`, and `460-12`, the OS maps `preloadedConfigFile` to the empty `/etc/carrier/config/0.xml` stub (or leaves it blank), leaving the phone with neither a carrier template nor a default data APN before activation. When `downloadedConfigFile` is empty and both `0.xml` and the read-only stock carrier XML (`404.xml`, `36.xml`, `446.xml`) match their pinned SHA-256 digests, setup now generates the managed `carrier.xml` from that verified stock template (stripping `446.xml`'s dead `10.0.0.200:80` proxy across all four Telecom MNCs) and permits a fail-closed pre-activation bootstrap before `cdsc_xml` is applied; once `cdsc_xml` is active, strict LTE data readiness checks resume. Stock `/etc/carrier/config/*.xml` files remain strictly read-only.
- **Fixes the r45 / r46 Passport (Q30) China Telecom incoming-call silent-audio regression**: Disassembly of stock `ims_rrm` `MediaDialog::populateBody` (`0xc621c`) confirms that with stock `Omit200OkSdp=1` (`0xb8e9c = 0121`), `ims_rrm` omits SDP in `200 OK` **only** when `SDPState == 0xd` (meaning precondition SDP negotiation already completed during `183 Session Progress` + `PRACK` or `UPDATE`), while non-precondition `180 Ringing` calls (`SDPState != 0xd`) and late-offer calls still attach a full SDP answer in `200 OK`. Forcing `Omit200OkSdp=0` in r45/r46 caused `200 OK` to emit a duplicate SDP answer after Telecom `183` + `PRACK`/`UPDATE`, re-triggering media session negotiation on Passport's data-centric Telecom attach path and leaving answered incoming calls silent. r47 restores `MediaDialog.Omit200OkSdp=1` while keeping `MediaDialog.EarlySdp=0` (`0xb8eb0: 0221 -> 0021`, suppressing duplicate/preview SDP on `180 Ringing`), verified by Unicorn machine-code emulation across all 12 MNCs and call-state branches.
- **Clearer SIM rejection diagnostics & PII-redacted media evidence**: Desktop, native mobile UI, and the AI skill now distinguish China Broadnet `460-15` (BB10 hardware lacks 700 MHz Band 28 and Broadnet is outside the three-carrier scope), 5G USIM cards containing an ISIM applet, active downloaded OTA carrier overrides, and unrecognized home networks (with redacted `MCC-MNC`). Redacted diagnostics now capture `MediaDialog`/`SDPState`/`RTPMediaSession`/`AudioMediaSession` state transitions while stripping SIP/tel URIs, Call-IDs, IPs, and subscriber numbers (preserving the `vpn_login` session UUID check). Telecom outbound SMS completion (`telecom_mo_ack`) and the automatic status-bar BlackBerry icon now apply across all four Telecom MNCs (`03` / `05` / `11` / `12`).
- Published r42/r43/r44/r45/r46 service payloads upgrade in place after stopping VoLTE, keeping existing backups and restoration intact. Offline emulation and unit tests do not replace real two-way call and SMS checks across regions and suffixes; historical per-model records remain scoped to their tested versions. The Windows EXE still has no Authenticode publisher signature.
