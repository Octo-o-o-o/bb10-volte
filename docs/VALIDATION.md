## 本分支 Mac 首次 Root 集成（不代表实刷验收）

当前源码新增 macOS 14+ 原生 Q10 首次准备、固定工具/依赖校验、个人密钥与镜像构建，以及单独确认后的 Terminal OS/radio 执行入口。工具从原作者 v4 包、官方 7-Zip 与固定 Homebrew bottles 获取，解包在个人工作目录；不安装 Homebrew、全局库或系统扩展。固定版本、架构和散列见[Mac Root 工具清单](../materials/macos-root-tools.json)。

维护者在当前 arm64 Mac 核验实际工具架构、依赖并成功运行原生 `--help`；随后已启动的 Q10 离线准备与 `batch` 构建自然完成，4 个原厂分区大小/散列与 radio 原散列核对通过，独立密钥、AppWorld 保留以及 unsigned OS / 原版 signed radio 产出已确认。源码 Root 诊断通过已有可信 SSH 只读验证有效 UID 0，临时 stage 清单前后均为原有 22 个，Mac USB 采集识别真实 NCM 接口与 `169.254.0.2`。详见[开发检查记录](../materials/macos-development-2026-10-29.json)。这些是源码、离线构建与既有 Root 连接验证，**不是手机首次 Root 刷写通过**。原生异常判断测试只证明已知输入下的暂停规则：任何错误/缺少证据都停止，Windows 的退出 73 例外不会在 Mac 放行。

**本分支没有对手机运行 `info`、`loader` 或 `flash`，没有重启/重刷本轮已启用的 Q10，也没有 Mac 实机首刷结果。** 原生刷写、密码交互、OS/radio 交接及刷后 Root 自动恢复需要另一轮明确授权的备机验收；源码集成、离线镜像构建和包自检不能代替它。已发布 r5 DMG 不包含本分支的新集成。用户随后选择先开发、不新增测试；已开始的操作自然结束后，没有再启动测试或实机操作。未 Root Q30 的具体硬件变体与匹配首刷材料未确认，后续单独准备，绝不复用 Q10 固件。

## 手动测试顺序

1. `status` 确认当前实例为 `running`，REGISTER200、LTE。
2. 另一台手机拨打 Q10；记录时间，Q10 接听后双方分别讲话，保持20秒，挂断。
3. Q10 用系统拨号器回拨；同样确认双方声音、20秒和4G。
4. 正常重启Q10，等待Root及服务就绪；重复2、3。
5. 断开电脑USB，等待数分钟后重复一次；确认不依赖电脑或限时窗口。
6. 最后重新连接并保存状态。重启后的实例、时刻和日志应单独记录。

不要将 REGISTER 的200、SUBSCRIBE/UPDATE/PRACK的200当成 INVITE200。完整呼叫至少核对 INVITE事务、ACK、会话结束，并结合真人声音反馈。

尚未测试其他型号/版本/运营商、漫游、切换小区、长期待机、紧急呼叫或网络侧策略变化。保留这些范围的明确标记。
