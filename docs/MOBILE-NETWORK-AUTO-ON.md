# 激活时自动打开移动网络

2026-11-08 本地候选：桌面 r41 / 手机版 0.1.0.42（networkon1108）。

用户点击安装、启用或继续未完成的 VoLTE 激活任务时，若移动网络的公开状态明确为 OFF，客户端会尝试打开移动网络。只有收到本次请求的确认并读回 ON，才重新核对 SIM 和原有适配条件、继续原任务。已开启时不重复发送请求；SIM 暂时不可读时仅允许开启网络后重新检查，不提前认定支持。

开启动作通过固定哈希的 BB10 cellular-control 原生 `power` PPS 命令执行，只发送 ON。状态刷新、开机后台、停用和卸载不会触发此动作。不开关循环、不修改数据服务或漫游设置，也不另外修改飞行模式设置。系统拒绝、超时、状态不明或通话忙时保留任务；用户可检查系统开关后继续。备份导出后若网络再次关闭，会保留备份并停止本次激活，不在同一次操作中反复打开。

请求意图写入原任务记录。进程中断或回执丢失后，继续任务会重新读取状态和 SIM；已经 ON 时不重发命令。已完成激活的回执优先于网络检查，避免把完成的操作误报为失败。旧版 r40 的实际载荷映射保留在 `materials/unified-payload-r40.json`，仍使用原有升级与恢复约束。

验证结果：Windows 相关测试共 318 项，279 项通过、39 项因平台或工具条件跳过；手机任务、引擎及相关 POSIX/签名测试在 Linux 容器执行，原生 Qt 控制器交互、Windows 成品离线自检、签名及两端 18 个后台文件一致性检查通过。独立 BAR 与 Windows 内置 BAR 相同。

扩展全量容器检查没有全通过：875 项中有 45 个错误、2 个失败、18 个跳过。主要原因是该 Qt 容器缺少 Tkinter、Python 3.11 缺少 `Path.is_junction`、只读挂载不支持两项临时文件测试；另一个 r18 升级测试仍断言旧文件差异集，任务开始前的 r40 映射已经具有相同差异。原始输出保留于工作区 `research/mobile-network-auto-on-20261108/`，没有将这些结果报告为通过。

本次未连接、安装或操作实机。自动开启后的设置界面、入网、VoLTE 通话/声音/短信/数据、生命周期结果仍待具体型号和运营商验收。已有型号与运营商范围不扩大，r40/mobile41 的设备记录不自动转为本版本通过。未公开发布。
