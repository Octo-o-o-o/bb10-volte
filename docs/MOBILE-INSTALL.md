# 手机原生应用：安装与使用

**简体中文** | [English](MOBILE-INSTALL.en.md)

这是与桌面端共存的原生 Cascades 应用，应用 ID 为 `com.octolab.bb10volte`。当前目标为手机 **0.1.0.6**、桌面 **r16**、管理协议 **2**，仍是待验收候选；正式公开下载以[验收记录](MOBILE-VALIDATION.md)为准。合并前 v5 的测试不能代替 v6 验收。安装应用与激活 VoLTE 是两个步骤；安装图标本身不会修改无线配置。

集中验收请直接使用[一次人工验收清单](MOBILE-MANUAL-ACCEPTANCE.md)。本轮 Passport 已由 v5 协议停用旧 r14 并恢复配置，任务为 waiting_reboot；已正常重启，记录时 Root SSH 尚未返回，原因未确定。尚未迁移新引擎，不能声称新候选 IMS 或通话已通过。先正常解锁、恢复原有入口，再查询并继续原任务，不要重新安装或重复停用来覆盖状态。

## 先判断使用哪条路径

| 手机状态 | 从哪里开始 | 是否可以全程不接电脑 |
| --- | --- | --- |
| 已 Root，已有可用的本机 BAR 安装器 | 手机浏览器下载 BAR，用现有安装器打开 | 具备本机路线；仍须验证该 Root 环境、最终安装版本与权限 |
| 已有有效 Root 终端、AutoRoot v4 本机 installer | 下载 bootstrap ZIP，在手机 Root 终端执行包内版本对应的命令 | 具备候选路线；不能由旧 v1 安装结果推定最终 v6 成功 |
| 已 Root，但没有本机安装器，也没有有效 Root 终端 | 先恢复已有 Root 的本机入口，或用桌面安装一次 BAR | 暂不能承诺从浏览器零引导完成 |
| 原厂未 Root | 使用现有 Windows/Mac 首次 Root 与安装流程 | 当前不能在手机上从零完成 |
| AutoRoot v2/v3 或其他 Root | 分别验证本地 helper、BAR 安装与启动权限 | 不套用 v4 的结论；Q20 v2 引擎支持不等于本机引导已验证 |

AutoRoot v4 的作者说明了 unsigned BAR 和本地权限 helper；这不代表任意“已 Root”系统都具备同一环境。参考[作者说明](https://bb10.root.sx/blog/autoroot-v4)。应用不会下载或执行 Root 漏洞，不会刷机，也不修改全局 PathTrust。

## 第一次装应用

1. 从同次候选交付或项目正式 HTTPS Release 获取目标 **0.1.0.6** 的 `.bar` 与校验信息。尚未公开发布时，不猜测下载 URL。已有 BAR Installer 时，用它打开文件；普通系统安装确认由你在手机上完成。
2. 只有 Root 终端时，下载同版本 `-bootstrap.zip` 到 Downloads。打开 ZIP 中的 `INSTALL.txt`，在已有 Root 终端运行其完整命令。命令使用设备已有 `/var/rootdata/installer`；包内包含 `pkg.bar`，不重新安装 Root。
3. 必须核对**同一安装任务的 SUD 最终 success，以及实际注册应用版本 0.1.0.6**。本轮只有 v1 得到 success 并注册为 0.1.0.1；v2 安装器在 120 秒超时后仍打印 completed，但没有 SUD success，注册版本仍是 0.1.0.1。保留输入并查询原任务，不能把 completed、解压、旧图标或旧版可打开当作升级成功，也不要连续重复安装。
4. 正常解锁，接受首次系统应用权限，打开 **BB10 VoLTE** 并核对界面应用版本。权限对话框本身不算界面已加载。应用随后检查内置入口哈希、发行者签名和运行环境，显示设备、SIM 运营商、可用操作和原因。无有效 Root 时按原方案恢复入口，不绕过系统权限或锁屏。

第一次下载的可信来源很重要。BAR 中自带的公钥只能保护后续组件，不能自行证明这个 BAR 来自项目。发行页必须同时公布 SHA-256 和固定发行公钥指纹；bootstrap ZIP、BAR、运行组件 ZIP 不可混用。

## 最简单的激活流程

**有旧安装或恢复任务时先续接。** 本轮现有 waiting_reboot 停用任务应先完成重启后核验。旧 r14 或 r15 服务完成恢复后，主按钮会按状态提供“更新手机服务”，管理页也有应用内置更新入口；使用最终 BAR 自带载荷迁移到 r16，不用另选同版本 ZIP。只有真正未安装服务的手机才执行下面的首次“开启”。

1. 选择备份位置。有已挂载 SD 卡时优先使用 SD 卡；没有时可使用手机内部 Documents。内部副本不能防止整机丢失或存储损坏，后续应另存一份。
2. 点击 **开启 VoLTE**。程序重新检查设备/原生文件/当前 SIM/通话空闲状态，保存原件，再导出备份并逐文件读回校验。备份失败时不会激活。任务在手机后台运行，离开应用后重新打开会查询同一任务。
3. 按提示使用电源菜单**正常重启**，解锁后等待约 3–5 分钟，再点击检查。Passport 进入或离开电信入网策略时可能还需要一次正常重启，界面会单独说明。
4. 显示 **IMS 已连接，待通话验收** 后，呼出、呼入各接通至少 35 秒，确认双方都有声音、通话维持 LTE，再在应用中完成四项确认。应用不会代拨电话。IMS 注册不等于通话已验收。
5. 短信另行测试长短、中英文收发与通知。人工通话验收只对当前开机、SIM 和程序载荷有效，换卡或更新后会重新要求确认。

以后换卡先关机再换，正常开机即可自动选择已支持的运营商。日常管理不需要 USB、SSH、桌面常驻或电脑联网。

## 更新、停用、恢复

- **应用内置版本更新**：旧服务完成停用恢复后，可直接应用当前 BAR 内置的签名载荷。该入口用于旧安装接管，不需要重新下载同版本 ZIP。
- **运行组件更新**：高级页面在线检查，或选择正式发行的更高版本 `-update.zip`。同版或旧版 ZIP 不用于普通更新。下载受大小限制、HTTPS 证书和域名限制；Root 中另行验签并生成私有快照。未知发行者、文件变动或路径异常会被拒绝。
- **应用界面更新**：安装同一应用 ID/作者 ID 的新版 BAR。组件 ZIP 不替换 C++/QML 界面。保留原应用身份是覆盖升级和应用设置保留的前提。
- **桌面旧引擎接管**：r14 → r16 与 r15 → r16 都要先停用、等待恢复、正常重启，再用新应用更新到管理协议 2，两条迁移路径分别验收。r14/r15 旧桌面不负责管理新协议；请升级到对应 r16 管理端。新桌面和手机共用设备端锁和事务记录，不能同时写入；不能承诺阻止已经越过旧校验的旧进程。
- **回滚**：停止服务并正常重启后，恢复已记录的上一个版本和其归档；不能选择任意文件作为原件。若旧引擎只认识真实桌面回执，而本次只有手机备份，回滚会拒绝，不会伪造桌面来源。
- **完整卸载服务**：应用内选择卸载。先停用、恢复、正常重启，然后继续核验并移除本项目拥有的载荷和启动入口；按提示再正常重启，验证原厂状态。原始备份与诊断仍保留。最后可在系统中移除应用图标。
- **直接删除图标**不会移除后台服务。未知文件、第三方改动、未结束的恢复事务会阻止清理；不会广泛删除目录。

备份与报告保存在所选存储的 `BB10-VoLTE/<随机操作ID>/`。**原始备份用于恢复，不要公开上传。** “诊断报告”和“兼容性报告”只包含白名单字段，不包含 IMSI、ICCID、IMEI、手机号、SIM 摘要或原始日志。导出位置在界面保留。

## 哪些设备可用

自动路线保持当前已研究的精确组合：OS `10.3.3.3216`、Q10 `SQN100-3`、Classic `SQC100-2`、Passport `SQW100-4`，以及移动 `460-00`、联通 `460-01`、电信 `460-11` 的符合条件 USIM。仍需通过当前实际环境和运营商开通检查。

高级实验页面有 **23 个明确选项**：旧有 4 个运营商配置，以及由共享定义生成并随签名包交付的 19 个准确硬件后缀试测配置。其中 13 组为受控手动候选，6 组 Passport 只读诊断。旧有通用配置仅接受 SQN100-3、SQC100-2、SQW100-4；其他后缀必须选择准确的试测配置，不能用通用配置绕过准入。仍须通过原生哈希、ABI、网络、原厂基线和恢复检查，每次手动启动都重新检查且核对已装配置一致；不自动开机运行。`SQC100-4` 仍是候选，不表示已完成真机通话验收，Passport 的旧恢复限制不放宽。

### 实验路线的恢复边界

上面的“原件导出备份 → 激活 → 完整更新/回滚/卸载”是**自动协议 2**流程，不直接套用到旧实验路线。普通 13 组试测不使用电信附着修改，其恢复依据是每次启动时保存的 PPS journal，不能宣称已经取得自动协议 2 的原件导出回执。需要另备个人数据；导出的试测检查记录带 `last_checked_not_live`，只是上次检查，不是实时状态或通话验收。

- **停止实验适配**：关闭旧实验自动启动标记并等待恢复，不只是发出停止请求。
- **更新实验适配**：须先停用并恢复、没有悬挂安装事务，再使用既有旧引擎更新流程。中断的 install-transaction 保留，不能盲重试或删除记录。
- **卸载实验启动项**：调用旧路线卸载启动入口，保留私有载荷和备份；这不等于自动协议 2 的完整文件移除。
- **没有新增实验回滚**：不能将自动协议 2 的回滚按钮或原件回执承诺套用于实验安装。只读 Passport 选项不会提供写操作。

未识别的设备也能生成部分兼容性报告；缺少一个属性不会导致所有事实都丢失。更多机型需要对应原生文件、Root 入口、无线频段/ABI、恢复和实际通话证据。仅扩展机型名称或取消哈希门槛无法可靠地新增支持。

已合入的 r15 桌面机型检查与试测定义由手机共用；这些是准入和诊断范围，不是新增手机版实机支持。构建和发布流程见[手机构建与发布](MOBILE-RELEASE.md)，交互细节见[界面契约](MOBILE-UX.md)。
