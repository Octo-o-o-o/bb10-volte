# 手机原生应用：安装与使用

**简体中文** | [English](MOBILE-INSTALL.en.md)

这是与桌面端共存的原生 Cascades 应用，应用 ID 为 `com.octolab.bb10volte`。当前候选为手机 **0.1.0.18**、桌面 **r19**、管理协议 **2**；后台服务保持已验证的 **r18**，不因界面版本更新而重装无线服务。v12/r18 已通过 Passport SQW100-4／移动和 Q20 SQC100-2／联通的完整恢复、卸载、重新安装、三次至少两分钟通话及双向长短/重复短信验收。v18 新界面和未测设备组合需要分别验收；准确范围见[验收记录](MOBILE-VALIDATION.md)。安装图标本身不会修改无线配置。

集中验收请使用[一次人工验收清单](MOBILE-MANUAL-ACCEPTANCE.md)。已有任务先按提示处理；正常重启并等到系统 Root 成功通知后，打开应用并检查原任务，不用重复启用或更新。v8 已由机主验证自动完成旧停用任务及 r16→r17 更新；v10 的通话验收记录已验证关闭重开后保留。

## 先判断使用哪条路径

| 手机状态 | 从哪里开始 | 是否可以全程不接电脑 |
| --- | --- | --- |
| 已 Root，已有可用的本机 BAR 安装器 | 手机浏览器下载 BAR，用现有安装器打开 | 具备本机路线；仍须验证该 Root 环境、最终安装版本与权限 |
| 已 Root，没有可用本机 BAR 安装器 | 使用 r19 桌面“更多 → 安装手机应用”引导一次 | 首次需要电脑；安装后在手机内点击管理 |
| 已有有效 Root 终端、AutoRoot v4 本机 installer | 可选 bootstrap ZIP 与包内版本对应命令 | 保留终端路线；每个目标版本须独立验证，不要求普通用户手输命令 |
| 原厂未 Root | 使用现有 Windows/Mac 首次 Root 与安装流程 | 当前不能在手机上从零完成 |
| AutoRoot v2/v3 或其他 Root | 分别验证本地 helper、BAR 安装与启动权限 | 不套用 v4 的结论；Q20 v2 引擎支持不等于本机引导已验证 |

AutoRoot v4 的作者说明了 unsigned BAR 和本地权限 helper；这不代表任意“已 Root”系统都具备同一环境。参考[作者说明](https://bb10.root.sx/blog/autoroot-v4)。应用不会下载或执行 Root 漏洞，不会刷机，也不修改全局 PathTrust。

**推荐的点击流程**：已有本机 BAR 安装器时直接点击安装。没有时，用 r19 桌面“更多 → 安装手机应用”，依次检查手机、选择匹配 BAR、确认安装，后续在手机内管理。既有 r18 桌面包不含此菜单。当前候选仍须以同一组最终产物完成验收。Q20 上 Android APK 调用 Root helper 的试验出现内核重启，已停止该路线，不提供 APK 引导包，也不把普通 ZIP 宣称为可点击的原生安装器。

## 第一次装应用

1. 从同次候选交付或项目正式 HTTPS Release 获取目标 **0.1.0.18** 的 `.bar` 与校验信息。尚未公开发布时，不猜测下载 URL。已有 BAR Installer 时，用它打开文件；普通系统安装确认由你在手机上完成。
2. 没有本机 BAR 安装器时，连接已 Root 的手机，在 r19 桌面选择“更多 → 安装手机应用”。检查型号后选择本次 BAR，再确认安装。桌面会核对完整包、应用身份、安装结果和所有安装文件。安装结果不明时保留同一任务，只检查，不重复提交。熟悉 Root 终端的用户也可选用同版本 bootstrap ZIP 中的 `INSTALL.txt`；这是替代路径，不是点击流程的必需步骤。
3. 必须核对**同一安装任务的 SUD 最终 success，以及实际注册应用版本 0.1.0.18**。桌面向导完成这些核验后才显示安装成功。旧 v2 曾在超时后打印 completed，却没有升级实际注册版本；每个新包仍须独立核验，不能把 completed、解压、旧图标或旧版可打开当作升级成功。
4. 正常解锁，接受首次系统应用权限，打开 **BB10 VoLTE** 并核对界面应用版本。权限对话框本身不算界面已加载。点击检查后，应用核对内置入口哈希、发行者签名和运行环境，显示设备、SIM 运营商、可用操作和原因。无有效 Root 时按原方案恢复入口，不绕过系统权限或锁屏。

第一次下载的可信来源很重要。BAR 中自带的公钥只能保护后续组件，不能自行证明这个 BAR 来自项目。发行页必须同时公布 SHA-256 和固定发行公钥指纹；bootstrap ZIP、BAR、运行组件 ZIP 不可混用。

## 最简单的激活流程

**有旧安装或恢复任务时先检查。** 按首页提示处理原任务，不能用新任务覆盖。旧多阶段任务若缺少新版安全保护，应用会保留现场并提示导出诊断，不会自动续跑。受支持的旧服务停用、恢复并正常重启后，主按钮提供“更新手机服务”；使用 BAR 内置载荷更新到 r18，不用另选同版本 ZIP。已有完整 r18 服务时，v18 不要求仅为更新界面再更新服务。只有真正未安装服务的手机才执行下面的首次“开启”。

1. 选择备份位置。有已挂载 SD 卡时优先使用 SD 卡；没有时可使用手机内部 Documents。内部副本不能防止整机丢失或存储损坏，后续应另存一份。
2. 点击 **开启 VoLTE**。程序重新检查设备/原生文件/当前 SIM/通话空闲状态，保存原件，再导出备份并逐文件读回校验。备份失败时不会激活。提交与核验期间显示等待提示并阻止重复操作；任务在手机后台运行，关闭后重新打开可手动查询同一任务。
3. 按提示使用电源菜单**正常重启**，解锁后先等待系统出现 Root 成功提示，再打开应用一次并点“检查”或“继续检查”。Root 生效前系统可能直接拒绝启动，应用内等待页此时无法运行；图标没反应时不要连续点击。网络就绪可能需要约 3–5 分钟；需要时再次手动检查。Passport 网络策略发生变化时可能还需要一次正常重启，界面会单独说明。
4. 检查后显示 **IMS 已连接，待通话验收**，呼出、呼入各接通至少 2 分钟，并再做一次呼出，确认双方都有声音、通话维持 LTE，再在应用中完成四项确认并保存。保存期间等待结果；回复延迟时应用会核对原记录，不重复保存或修改无线设置。关闭重开显示的是标明“上次检查”的验收记录；手动检查才能确认当前开机和 SIM。应用不会代拨电话。IMS 注册不等于通话已验收。
5. 短信另行测试长短、中英文收发与通知。人工通话验收只对当前开机、SIM 和程序载荷有效，换卡或更新后会重新要求确认。

以后换卡先关机再换，正常开机即可自动选择已支持的运营商。日常管理不需要 USB、SSH、桌面常驻或电脑联网。

首次安装或升级后，如果没有缓存，首页会请你手动检查一次。以后打开、切回前台或解锁时先显示上次结果，不自动检测；换卡、重启或需要确认实时状态时请主动检查。旧状态不能直接授权更改，通话验收保存时也会重新检查当前 SIM、开机和 IMS。应用检查在 150 秒没有实际校验进度时超时，整次请求上限为 15 分钟；其他独立的底层命令超时不变。

## 更新、停用、恢复

- **应用内置版本更新**：旧服务完成停用恢复后，可直接应用当前 BAR 内置的签名载荷。该入口用于旧安装接管，不需要重新下载同版本 ZIP。
- **运行组件更新**：高级页面在线检查，或选择正式发行的更高版本 `-update.zip`。同版或旧版 ZIP 不用于普通更新。下载受大小限制、HTTPS 证书和域名限制；Root 中另行验签并生成私有快照。未知发行者、文件变动或路径异常会被拒绝。
- **应用界面更新**：安装同一应用 ID/作者 ID 的新版 BAR。组件 ZIP 不替换 C++/QML 界面。保留原应用身份是覆盖升级和应用设置保留的前提。
- **桌面旧引擎接管**：受支持的旧载荷更新到 r18 时，要先停用、等待恢复、正常重启，再用新应用更新到管理协议 2；各起点分别验收。请使用 r19 桌面管理端；已有 r18 桌面仍可管理未变的 r18 服务，但没有新图形首装入口。新桌面和手机共用设备端锁和事务记录，不能同时写入；不能承诺阻止已经越过旧校验的旧进程。
- **回滚**：按提示满足所需停用和正常重启条件，使用归档回滚上次更新的服务或管理组件；不能选择任意文件作为原件。为保护任务，管理组件可能保留新版，无法安全回退的旧管理组件会被拒绝。若旧引擎只认识真实桌面回执，而本次只有手机备份，回滚会拒绝，不会伪造桌面来源。
- **完整卸载服务**：应用内选择卸载。先停用、恢复、正常重启，然后继续核验并移除本项目拥有的载荷和启动入口；按提示再正常重启，验证原厂状态。原始备份与诊断仍保留。最后可在系统中移除应用图标。
- **直接删除图标**不会移除后台服务。未知文件、第三方改动、未结束的恢复事务会阻止清理；不会广泛删除目录。

备份与报告保存在所选存储的 `BB10-VoLTE/<随机操作ID>/`。**原始备份用于恢复，不要公开上传。** “诊断报告”和“兼容性报告”只包含白名单字段，不包含 IMSI、ICCID、IMEI、手机号、SIM 摘要或原始日志。导出位置在界面保留。

## 哪些设备可用

自动路线保持当前已研究的精确组合：OS `10.3.3.3216`、Q10 `SQN100-3`、Classic `SQC100-2`、Passport `SQW100-4`，以及移动 `460-00`、联通 `460-01`、电信 `460-11` 的符合条件 USIM。仍需通过当前实际环境和运营商开通检查。

高级实验页面有 **23 个明确选项**：旧有 4 个运营商配置，以及由共享定义生成并随签名包交付的 19 个准确硬件后缀试测配置。其中 13 组为受控手动候选，6 组 Passport 只读诊断。旧有通用配置仅接受 SQN100-3、SQC100-2、SQW100-4；其他后缀必须选择准确的试测配置，不能用通用配置绕过准入。仍须通过原生哈希、ABI、网络、原厂基线和恢复检查，每次手动启动都重新检查且核对已装配置一致；不自动开机运行。`SQC100-4` 仍是候选，不表示已完成真机通话验收，Passport 的旧恢复限制不放宽。

### 实验路线的恢复边界

上面的“原件导出备份 → 激活 → 完整更新/回滚/卸载”是**自动协议 2**流程，不直接套用到旧实验路线。普通 13 组试测不使用电信附着修改，其恢复依据是每次启动时保存的 PPS journal，不能宣称已经取得自动协议 2 的原件导出回执。需要另备个人数据；导出的试测检查记录带 `last_checked_not_live`，只是上次检查，不是实时状态或通话验收。

- **停止实验适配**：关闭旧实验自动启动标记并等待恢复，不只是发出停止请求。
- **更新实验适配**：须先停用并恢复、没有悬挂安装事务，再使用既有旧引擎更新流程。中断的 install-transaction 保留，不能盲重试或删除记录。
- **卸载实验启动项**：调用旧路线卸载启动入口，保留私有载荷和备份；这不等于自动协议 2 的完整文件移除。
- **没有新增实验回滚**：不能将自动协议 2 的回滚按钮或原件回执承诺套用于实验安装。只读 Passport 选项不会提供写操作。

未识别的设备也能生成部分兼容性报告；缺少一个属性不会导致所有事实都丢失。更多机型需要对应原生文件、Root 入口、无线频段/ABI、恢复和实际通话证据。仅扩展机型名称或取消哈希门槛无法可靠地新增支持。

已合入的 r15 桌面机型检查与试测定义由手机共用；这些是准入和诊断范围，不是新增手机版实机支持。构建和发布流程见[手机构建与发布](MOBILE-RELEASE.md)，交互细节见[界面契约](MOBILE-UX.md)。
