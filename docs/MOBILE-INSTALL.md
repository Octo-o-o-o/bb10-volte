# 手机原生应用：安装与使用

**简体中文** | [English](MOBILE-INSTALL.en.md)

这是与桌面端共存的原生 Cascades 应用，应用 ID 为 `com.octolab.bb10volte`。本分支生成候选包，正式公开下载必须以[验收记录](MOBILE-VALIDATION.md)为准。安装应用与激活 VoLTE 是两个步骤；安装图标本身不会修改无线配置。

## 先判断使用哪条路径

| 手机状态 | 从哪里开始 | 是否可以全程不接电脑 |
| --- | --- | --- |
| 已 Root，已有可用的本机 BAR 安装器 | 手机浏览器下载 BAR，用现有安装器打开 | 可以，仍需验证该 Root 环境的本地权限入口 |
| 已有有效 Root 终端、AutoRoot v4 本机 installer | 下载 bootstrap ZIP，在手机 Root 终端执行包内版本对应的命令 | 可以 |
| 已 Root，但没有本机安装器，也没有有效 Root 终端 | 先恢复已有 Root 的本机入口，或用桌面安装一次 BAR | 暂不能承诺从浏览器零引导完成 |
| 原厂未 Root | 使用现有 Windows/Mac 首次 Root 与安装流程 | 当前不能在手机上从零完成 |
| AutoRoot v2/v3 或其他 Root | 分别验证本地 helper、BAR 安装与启动权限 | 不套用 v4 的结论；Q20 v2 引擎支持不等于本机引导已验证 |

AutoRoot v4 的作者说明了 unsigned BAR 和本地权限 helper；这不代表任意“已 Root”系统都具备同一环境。参考[作者说明](https://bb10.root.sx/blog/autoroot-v4)。应用不会下载或执行 Root 漏洞，不会刷机，也不修改全局 PathTrust。

## 第一次装应用

1. 用手机浏览器从项目正式 HTTPS 页面或正式 Release 下载对应版本 `.bar`。已有 BAR Installer 时，使用其打开这个文件，等待安装完成，再打开 **BB10 VoLTE**。
2. 只有 Root 终端时，下载同版本 `-bootstrap.zip` 到 Downloads。打开 ZIP 中的 `INSTALL.txt`，在已有 Root 终端运行其完整命令。命令使用设备已有 `/var/rootdata/installer`；包内包含 `pkg.bar`，不重新安装 Root。
3. 保留下载文件直到安装器给出最终结果。超时、开始解压或提交安装任务，都不等于成功。先检查同一任务，不连续重复安装。
4. 打开应用。应用先检查内置入口哈希、发行者签名和运行环境，然后显示设备、SIM 运营商、可用操作和原因。无有效 Root 时给出恢复入口提示。

第一次下载的可信来源很重要。BAR 中自带的公钥只能保护后续组件，不能自行证明这个 BAR 来自项目。发行页必须同时公布 SHA-256 和固定发行公钥指纹；bootstrap ZIP、BAR、运行组件 ZIP 不可混用。

## 最简单的激活流程

1. 选择备份位置。有已挂载 SD 卡时优先使用 SD 卡；没有时可使用手机内部 Documents。内部副本不能防止整机丢失或存储损坏，后续应另存一份。
2. 点击 **开启 VoLTE**。程序重新检查设备/原生文件/当前 SIM/通话空闲状态，保存原件，再导出备份并逐文件读回校验。备份失败时不会激活。任务在手机后台运行，离开应用后重新打开会查询同一任务。
3. 按提示使用电源菜单**正常重启**，解锁后等待约 3–5 分钟，再点击检查。Passport 进入或离开电信入网策略时可能还需要一次正常重启，界面会单独说明。
4. 显示 **IMS 已连接，待通话验收** 后，进行一次呼出、一次呼入，确认双方都有声音、通话维持 LTE，再在应用中完成四项确认。应用不会代拨电话。IMS 注册不等于通话已验收。
5. 短信另行测试长短、中英文收发与通知。人工通话验收只对当前开机、SIM 和程序载荷有效，换卡或更新后会重新要求确认。

以后换卡先关机再换，正常开机即可自动选择已支持的运营商。日常管理不需要 USB、SSH、桌面常驻或电脑联网。

## 更新、停用、恢复

- **运行组件更新**：高级页面在线检查，或选择正式发行的 `-update.zip`。下载受大小限制、HTTPS 证书和域名限制；Root 中另行验签并生成私有快照。未知发行者、旧版本、文件变动或路径异常会被拒绝。
- **应用界面更新**：安装同一应用 ID/作者 ID 的新版 BAR。组件 ZIP 不替换 C++/QML 界面。保留原应用身份是覆盖升级和应用设置保留的前提。
- **桌面旧引擎接管**：先停用、等待恢复、正常重启，再用新应用更新到管理协议 2。已发布 r14 不负责管理新协议；请同时升级桌面到该分支对应版本。新桌面和手机共用设备端锁和事务记录，不能同时写入。
- **回滚**：停止服务并正常重启后，恢复已记录的上一个版本和其归档；不能选择任意文件作为原件。若旧引擎只认识真实桌面回执，而本次只有手机备份，回滚会拒绝，不会伪造桌面来源。
- **完整卸载服务**：应用内选择卸载。先停用、恢复、正常重启，然后继续核验并移除本项目拥有的载荷和启动入口；按提示再正常重启，验证原厂状态。原始备份与诊断仍保留。最后可在系统中移除应用图标。
- **直接删除图标**不会移除后台服务。未知文件、第三方改动、未结束的恢复事务会阻止清理；不会广泛删除目录。

备份与报告保存在所选存储的 `BB10-VoLTE/<随机操作ID>/`。**原始备份用于恢复，不要公开上传。** “诊断报告”和“兼容性报告”只包含白名单字段，不包含 IMSI、ICCID、IMEI、手机号、SIM 摘要或原始日志。导出位置在界面保留。

## 哪些设备可用

自动路线保持当前已研究的精确组合：OS `10.3.3.3216`、Q10 `SQN100-3`、Classic `SQC100-2`、Passport `SQW100-4`，以及移动 `460-00`、联通 `460-01`、电信 `460-11` 的符合条件 USIM。仍需通过当前实际环境和运营商开通检查。

高级实验页面保留已有单运营商手动路线，包含联通、移动、电信和电信 460-11 附着配置。其他 Q10/Classic 只有通过现有原生哈希、ABI、网络、原厂基线与恢复检查后，才提供手动安装/启动；不自动开机运行。`SQC100-4` 是适配候选，模拟准入通过不代表真机通话已通过。Passport 不绕过旧引擎的恢复限制。

未识别的设备也能生成部分兼容性报告；缺少一个属性不会导致所有事实都丢失。更多机型需要对应原生文件、Root 入口、无线频段/ABI、恢复和实际通话证据。仅扩展机型名称或取消哈希门槛无法可靠地新增支持。
