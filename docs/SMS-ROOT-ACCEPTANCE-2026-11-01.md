## 已修复

- Windows 原版固件升级原先只识别 `Writing 100%`，无法识别真实 autoloader 的
  `[ Writing 0x0092C044 ] [############## 100 ##############]` 格式。
  现在两种格式均可识别，同时拒绝 `Writing 100 bytes`、十六进制地址中的 `100` 和未完成进度。
  使用既有 Passport 实机刷写日志回放验证，不包含日志中的设备标识。
- Windows Root 原先可能接受只有写入完成、只有 `Done.`，或者退出码为零但存在安全错误的结果。
  现在普通成功要求写入完成、后续 `Done.`、退出码零且无错误。
  仅 OS 阶段在完整写入后出现两个明确的 AutoRoot v4 安全错误、退出码 73 且无其他错误时，
  保留已知配方的继续条件。该例外不会应用到 radio 或原版固件升级。
- Windows Root 原先先启动刷机子进程，再检查日志是否已存在；重复打开同一阶段窗口可能先触发第二次刷写。
  现在在启动子进程前独占创建日志，已有阶段不会再次启动。
- Windows Root 现在处理没有换行的末尾输出，避免遗漏最后一个错误；结果文件原子写入，
  密码提示及设备标识使用已有脱敏规则，子进程显式接收已打开的控制台输入。
- 原版系统首次开机会通过 DHCP 分配新的 USB `/30` 地址；固定查询 `169.254.0.1`
  会漏掉尚未 Root 的手机。现在只从唯一 BlackBerry 的活动 USB 接口推导对端，绑定本机地址，
  Windows 另外绑定接口编号。拒绝多个候选接口、普通 `/16` APIPA、非链路本地地址、
  HTTP 重定向和过大的发现响应；Mac 同时读取并检查真实网络掩码。
  Root 前置 SSH 检查也绑定实际对端，保留严格主机密钥校验，
  不把旧地址连接失败或没有已保存配置当成当前手机未 Root 的证据。
- Passport 的日志长时间只显示 `Resetting Device`，终止后才写出一行被脱敏的设备标识或密码提示，
  原始提示未被保留，不能仅凭该行确定等待原因。已复现未换行的密码请求会被缓冲的问题；
  现在识别到完整密码请求即写出不含密码或原文的等待状态，无需等进程退出。
  已终止的首次尝试没有观察到镜像写入；原日志、结果与锁状态完整保留，未记为 Root 成功。
- Q20 首次安装私有短信候选后，IMS 在 QNX 动态加载器内触发 SIGSEGV。
  修订版保留原来的两个 LOAD 头；同机依赖枚举通过，旧版则可稳定复现加载器故障。
  后续修订版已实际启动，原生映射中的代码为 RX、缓存为 RW；该次注册超时，尚无短信或通话验收。
- 新刷 AutoRoot v4 的手机可能尚无 `/var/addons`；只读预检不再要求它预先存在，
  激活时才创建缺失目录。文件或符号链接占位仍拒绝。此修复已在新刷 Passport 上完成安装。
- Root-v2 没有 `/var/rootdata`，通用权限诊断改用 `/var` 下的随机专用目录，
  清理器仅接受诊断的三个确切文件，不能借此清理载荷或其他文件。
- Mac 原生工具的管道输出会缓冲密码提示；现在输出经过终端，输入仍直连关闭回显的原生终端，
  密码不经过日志转发。真实终端回归和 Q20 原生提示均已验证。
- 固定上游包中的 `loaders.dat` 首个资源 LDR_00 覆盖了归档头，Q20 实机报 CRC 不符。
  改从同一固定散列的 `cap.exe` 提取对应完整签名 loader，检查源文件、压缩片段、解压结果散列及 gzip CRC。
  不修改损坏数据的 CRC，也不接受任意 loader；Q20 已成功加载修复后的资源。
- Mac 源码运行与应用包共用用户目录中的刷写锁，避免换源码目录后看不到正在进行的阶段。
- Mac 原生工具写入和签名提交完成后，多余的 USB 重连曾导致 `LIBUSB_ERROR_OTHER`。
  固定散列与逐字节补丁只跳过最后一次多余重连，保留原有重启、关闭和清理。
  ARM64/Intel 共 16 组函数仿真通过；ARM64 签名校验、Q20 读取版本、无线固件和 Root 两阶段实写正常结束。
  原版 OS 的失败回执原样保留，并另记后续开机读回与无线固件补写，未更改成功判定。
  见[修复范围和等价源码改动](MACOS-NATIVE-TOOL-REPAIR.md)。
- Mac 当前 Python 运行环境读取 USB 元数据时返回 `EHOSTUNREACH`，同一对端通过系统 curl 返回正常 XML。
  Mac 发现请求改用系统 HTTP 客户端，限定唯一 USB `/30` 对端和源地址、禁用代理及 curlrc，
  不跟随重定向、不传凭据，并限制时间和响应大小。Q20 原版系统机型、版本和首次设置状态已实际读回。
