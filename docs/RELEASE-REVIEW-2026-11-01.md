## 发现、修复与证据

1. **原生短信候选会默认替换全部已支持机型的 IMS 镜像。** `device/ims_image.py` 在常规启动时无条件进入 `sms_ack_binary`，但候选自身记录 QNX loader 和网关尚未验证。r13 将它改为显式 `sms_ack=True` 才启用，日常服务保持原有语音镜像；源码、生成器、仿真及离线验证仍完整保留。`tools/verify_sms_ack.py` 使用本机固定哈希原厂文件，验证默认两种语音镜像与已知哈希相同，再对显式候选执行九种组合、三种装载基址的 27 次调用点验证。默认路径回归还验证没有调用 shim。
2. **Q20 移动最终已验收的旧载荷未进入发布识别清单。** `tools/q20_managed.py` 会在上传检查器之前拒绝缺失的 `a517c79c…` 清单。已与历史设备回读文件核对 SHA-256，并在 `materials/q20-managed-adapter.json` 增补该值、保留先前版本。回归使用真实脱敏文件清单，确认已知版本进入检查，改动后的清单在上传前拒绝。历史验收边界见 `materials/q20-mobile-autostart-validation.json`。
3. **固件导入失败提示把所有机型都称作 `.7z`。** Q20 原版输入实际是 EXE；已将中英文提示改为保留所选原版固件格式，下载、哈希和机型检查不变。
4. **新增诊断选择测试未模拟 Mac 的实际窗口状态。** Mac 的 Tk 不向未映射的控件派发原生选择事件；已分别复现隐藏与映射窗口的行为。测试现先映射透明窗口并处理事件，再验证选择、换行和刷新清空；界面实现无需修改。

## 核查覆盖

- Root／升级：Q10、Q20、Passport 机型与材料绑定；旧／当前／未知／较新 OS；独立清空确认；共享写入锁、阶段令牌和防重复执行；中断状态及升级后 OS 回读；Windows 与 Mac 原生流程。
- 连接：现有 Root 和身份检查、手机配对路径与权限、恢复记录和用户提示。未关闭 SSH 主机校验或 TLS 证书验证。
- 短信：PPS 字段保存／恢复、旧安装升级、并发配置拒绝覆盖；原生 shim 的可复现构建、ARM／Thumb 调用约定、缓存冲突／失效及 ELF 结构；诊断报告隐私边界。
- 桌面：SQC100-4 的适配边界、安装许可、完成页、中英文、Root 按钮状态和打包资源。
- 发布：公开文件白名单、载荷哈希、源码 ZIP 往返核验、两平台实际包自检、Mac Developer ID 签名及 Apple 公证、R2／GitHub 完整下载校验、中英文官网静态与浏览器回归。最终结果和精确制品哈希随 Release 的 `release-validation.json` 提供。

## 明确未验收

没有对日用手机刷写、重启、改写 IMS 或发送短信。旧 OS → 原版升级 → Root → 连接的完整实机闭环、首次 Root、原生短信候选的 QNX 加载和网关接受、真实重复短信消除、Intel Mac 执行、极空间大固件完整下载及长期稳定性仍未验收。r7/r8 的九组合语音／换卡／显示记录不替代这些项目。短信发送策略也尚无实机验收，不能把软件回归结果称为真实短信修复成功。

Mac＋Q20 的 r10 连接／USB 拔插历史验收与 r13 的包级验证分别记录。Windows EXE 无 Authenticode 签名；Mac 使用既有 Developer ID、公证和装订票据。平台支持下限与实际测试机器范围分别说明。
