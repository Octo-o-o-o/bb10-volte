The local `0.3.3-r4` diagnostic test build recognizes Telecom `ctlte`. Check details and exported reports distinguish profile matching, actual data connectivity and individual baseline configuration observations. Only fixed public APN names are exported; other names become `other`. Existing custom profiles are not silently changed: reselect the Telecom template or review its APN list. Non-default settings do not establish corruption or ownership; preflight never resets an APN or deletes overrides. Old reports lack these details. Device data and baseline gates still apply, and Q20 Telecom hardware acceptance is pending.

Version 0.3.3 adds “More → Community research and adaptation progress.” Reports include exact-match community evidence and read-only incoming configuration snapshots. They do not establish call acceptance. Passport automatic installation, start and restore are paused; see [community research](COMMUNITY-RESEARCH.en.md).

`0.3.3-r3` uses **连接手机 / Connect phone** and **连接帮助 / Connection help**. SSH file paths and aliases move to **更多 → 高级连接设置 / More → Advanced connection settings**. This flow is included in the Windows EXE, Mac DMG and source; r6 and older binaries retain some labels described below.

On first use, connect and unlock the phone, then choose Connect phone. Connection help distinguishes USB problems, rejected authorization, changed host identity and unverified Root. It can inspect an owner-selected original Root folder, confirm its source and create local paths from a unique login-key/host-key pair. Multiple or incomplete materials require a narrower folder or phone authorization. Advanced configuration imports keep their original paths.

On reopening, the app rechecks the last successful connection once without automatically installing, flashing or enabling services. Incomplete phone pairing retains its original key, request ID and current step; multiple requests require explicit selection. Completed image preparation can be revalidated and resumed, while an uncertain flash outcome stays blocked. A failed connection never automatically routes to first Root preparation.

The BlackBerry 10 desktop GUI uses the same fixed workflow as the CLI. Windows users can use the [standalone EXE](WINDOWS-EXE.en.md); macOS users can use the `.app` described in the [DMG guide](MACOS.en.md). Users do not need to install Python separately. Source execution requires Python 3.14 with Tk and OpenSSH. Both require a reachable device and your own verified root SSH configuration. The current Q10 passed Mac USB networking, daily checks and calls; see the [Mac connection guide](MACOS.en.md) for the exact scope. No AI account or cloud service is needed. The first UI is in Chinese; this guide describes its controls.

On macOS, the connection card provides short cable/unlock and personal-profile/recovery instructions plus **Mac 连接说明 / Mac connection help**, available offline in the app. The [guide](MACOS.en.md) covers unrooted phones, rooted phones without files and rooted phones with personal materials. Without old Windows files, a working phone Root terminal can authorize an independent Mac key; `PAIR` persistently appends phone authorization. With neither materials nor a working Root terminal, direct connection is unavailable. The app does not automatically change IP settings, install old Link or weaken host verification.

These UI instructions and First use fixes belong to the current repository source. Published `0.3.2-r5` does not include them: its main window passed real-device checks, but the First use Python `-c` Root probe can be rejected by phone policy and misreported as a connection problem, with incomplete USB facts. Source tests are not new-DMG acceptance.

For source execution, extract the complete release and double-click `Start-GUI.cmd`, or run `python tools/gui.py`. Keep the complete directory. Do not regenerate a manifest on a customer's machine to bypass a package mismatch.

1. Check device discovers saved or known local owner configurations and matches legacy `q10-root` aliases. You may import your own profile; custom aliases are under More → Connection options. Missing setup can be handled by First use; see [the setup guide](FIRST-RUN.en.md). Strict host verification remains enabled.
2. Select a preset or **自定义 / Customize**. Edit MCC/MNC, data/IMS APNs, IP family, domain, waits and autostart; import/export JSON. Profile ID and stock configuration fingerprints are under the Advanced tab. Q20/Q30 and untested operators reveal an explicit experimental opt-in. Changes invalidate preflight. See [profiles](PROFILES.en.md). Then click **检查设备 / Check device**: it recognizes the device and checks OS, root, native hashes, SIM, LTE, selected data APN, stock carrier configuration and existing state. Four probe modules and a configuration request are temporarily uploaded; executed scripts are individually trusted and cleaned up on success. It does not change telephony settings.
3. Resolve blocked or waiting checks. The main view shows only actionable checks; **检查详情 / Check details** retains the complete results. Confirm the backup, carrier VoLTE provisioning and absence of an active call. **安装并验证 / Install and verify** becomes available only when required checks pass. A complete stopped service offers **启动并验证 / Start and verify**; update is available under **更多 / More**. An existing active service must first be stopped and restored.
4. Installation verifies the fixed package, repeats phone-side preflight, writes the release/profile, reads it back and starts IMS validation. Autostart follows the selected profile. Registration observation defaults to 180 seconds and is configurable. Keep USB connected; do not swap SIMs or use another installer. First activation may briefly reload the radio.
5. IMS registration requires a live manager, live native process, LTE and connected IMS with `200 OK`. It does not prove calls work. Verify incoming/outgoing calls, audio in both directions, continued LTE, unplugged operation and a normal reboot. A desktop timeout reports pending registration, not automatic success or a repeated installation.

**Reboot timing after installation:** In the v0.3.2 Q10 normal-reboot trial on 2026-10-28, system startup to IMS registration took approximately **3 minutes 48 seconds**. BB10 and Root startup accounted for about **3 minutes**; registration took about **45 seconds after Root was ready** (44.7 seconds measured). **45 seconds is not the total boot time.** This is one Beijing Unicom device's result; timing varies with the device and network. After the desktop, 4G indicator or Root success notice appears, wait for verified IMS registration before testing calls. Prefer a normal reboot from the phone power menu; an earlier computer-triggered reboot produced a black screen for an undetermined reason. The main window shows a brief call-acceptance reminder; detailed timing remains in this guide.

Desktop revision 2 removes the permanent sidebar and technical checklist from first launch. **更多 / More** contains service status, disable/restore, sanitized report export, connection options, help and licenses. Internal error codes remain in exported reports; the main view shows a suggested next step. The full compatibility checks and phone payload are unchanged.

**启动并验证 / Start and verify** starts a complete current installation. **查看服务状态 / Status** reads current state. **停用并恢复 / Disable and restore** turns off startup and checks restoration of the project's changes. **导出检查报告 / Export report** saves only allowlisted diagnostic fields, without full SIM/device identifiers, keys, host addresses or raw SIP logs. Reports are never uploaded automatically. Change legacy or custom SSH aliases under **More → Connection options**.

After a connection failure, recheck before retrying. Interrupted writes leave an installation transaction receipt or an incomplete directory and block replacement. Arbitrary interrupted installs do not yet have automatic repair; preserve the files for maintainer inspection. First use provides Windows Q10 preparation/flashing; this branch also adds experimental native preparation and separately confirmed staged execution on macOS 14+, without hardware first-flash acceptance. Both erase phone data when flashing; see [setup scope](FIRST-RUN.en.md). Other models remain outside the recipe; native Mac errors pause without the Windows exit-73 exception.

Q20 remains experimental. Passport shows a provider-lifecycle hold and automatic mutations are paused. Explicit opt-in never bypasses OS/native hashes or SIM compatibility. Only one Beijing Unicom Q10 has call evidence. Public-data Mobile, Telecom and other Unicom templates are untested; ISIM remains unsupported. Reports include selected profile and file fingerprints; keep personal details out of profile labels. See [compatibility](COMPATIBILITY.en.md). Never flash the bundled Q10 Root images onto Q20/Q30.

After the author reported boot-animation hangs, experimental combinations require autostart off under Customize → Runtime options and a fresh preflight. Desktop/CLI/phone gates enforce manual start; the accepted Q10 baseline retains its prior behavior.
