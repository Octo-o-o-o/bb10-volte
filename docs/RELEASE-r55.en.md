# Windows r55 and mobile 0.2.1.0

- **Flash failure diagnostics & safe pause recovery**: Initial Root flashing and stock OS upgrades now record whether the autoloader actually entered writing (`writing_started`). When flashing exits incomplete (such as missing BlackBerry USB Bootrom drivers, connection timeout, or an interrupted password prompt), the console pauses instead of closing immediately and attaches a redacted excerpt to feedback ZIPs. When `root-flash.lock` is active, both wizards display "Review flash log and clear pause…" so owners can inspect the log and unlock without deleting images, keys, or logs. Windows driver preparation and installation are decoupled from `root-flash.lock` and remain enabled even when booted USB networking already works.
- **Windows PowerShell driver verification & non-ASCII SSH key fixes**: Driver signature checks and installation now prefer System32 Windows PowerShell 5.1 with `-ExecutionPolicy Bypass`, preventing `CalledProcessError` under restrictive execution policies. Key generation passes `-C ''` and `.pub` readers tolerate non-ASCII Windows usernames/hostnames, eliminating `UnicodeDecodeError`.
- **Legacy-directory blocker guidance & `cleanup-stage` lock contention fix**: `unified_install.probe()` maps legacy/Root-scheme assertions (such as `unvalidated_legacy_installation`) to structured `scope_error` guidance on both mobile and desktop instead of generic `remote_operation_failed`. `cleanup-stage` now runs outside non-blocking `management_lock()`, preventing lock collisions during boot handoff or disable restoration.
- **Allowlisted runtime `error_code` & pre-native LTE-only rollback**: `public_status()` now surfaces allowlisted `error_code` values on current-boot failures across mobile, desktop, and feedback reports; pre-journal prepare failures roll back owned LTE-only/network-selection overrides when idle so phones are not left stuck on "Searching". Also clarifies LTE-wait guidance, adds an in-call Mobile Network caution, retries transient Windows Defender read locks during firmware extraction, guides Passport users from the legacy window to Automatic carrier setup, and updates `kt_isim_trial.py` default `--host` to `bb10-root`.

This is an experimental release. The macOS download remains frozen at r43.
