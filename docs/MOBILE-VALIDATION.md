## Passport 上已实测的底层能力

设备范围仅为 **Passport SQW100-4 / OS 10.3.3.3216 / AutoRoot v4**：

- 25 个 Python 文件通过设备 Python 3.2.2 编译。
- 坏签名被拒绝；伪造 ZIP 的实际展开上限被拒绝。
- QNX 跨进程双层锁争用生效，持锁进程收到 SIGKILL 后锁可由内核释放。
- UID 1000 通过现有 __root 桥获得 Root；校验后的私有 entry 副本执行并清理。
- 导出子进程使用 UID 1000 / GID 1001、清空附加组；文件权限 0600，逐文件读回成功。
- 六个原生文件的兼容性报告可生成；这不授予其他机型准入。
- 新 SPAWN_NEWAPP 后台启动路径中 appid = sid = pid，父进程退出后任务仍完成；不把普通 fork/setsid 当作跨应用生命周期保证。
- 四份原始文件已导出到手机，并另在电脑核对哈希一致。原始内容、个人存储位置和回执保留在私有资料中。

这些是受控本机探针结果。实际 Cascades 应用中的完整提交、退出、重新打开与续接仍需人工操作。

## 应用安装与当前手机停留位置

| 步骤 | 已观察结果 | 判定 |
| --- | --- | --- |
| v1 BAR | SUD 最终 success，应用注册 manifest 为 0.1.0.1 | 仅 v1 安装成功 |
| v2 BAR 替换 | 外部 installer 打印 completed，但没有 SUD success，实际注册版本仍为 0.1.0.1 | 升级未验证成功；不能按 completed 判通过 |
| v5 文件 | 已复制到手机下载区，没有完成安装 | 不能称 v5 已安装 |
| 首次原生启动 | 停在系统应用权限界面；尚未人工解锁或接受 | 未证明 UI 已完整加载或普通应用沙箱流程可用 |
| v5 协议管理旧 r14 | disable 成功恢复配置，任务进入 waiting_reboot | 旧服务已停用与恢复，后续待核验 |
| 正常重启 | 已执行正常 shutdown 重启；记录时 Root SSH 尚未返回 | 原因未确定，可能与解锁或 AutoRoot 启动有关；不能断言 Root 损坏或恢复已完成 |
| 新引擎与无线 | 尚未迁移新引擎，未取得新候选 IMS/通话成功证据 | 待人工验收 |

继续时先正常解锁并检查原有 Root 入口，再用已确认安装的最终 **0.1.0.6** 应用查询、继续**现有 waiting_reboot 任务**。不要重新提交 disable，不要把当前状态当作新装完成。最终 BAR 必须同时取得对应安装任务的 SUD 最终 success 和实际注册版本 0.1.0.6；旧图标或旧版能打开都不够。

- v6 / r16 的 Mac 全量测试、最终独立复评和文档收尾后产物回读；Windows 745 项与真实 SDK 构建已通过。检查签入的 19 个 exact trial 与原生 23 项一致，保留 13 组受控试验与 6 组 Passport 只读路线，不能将其变成新增自动支持。
- 正常权限确认、Cascades 真实加载；中英、小方屏和 Passport 大方屏、键盘/触控/文件选择。
- 现有停用任务跨重启完成；通过应用内置更新入口执行 r14 → r16 迁移。另单独验证 r15 → r16，不能由 r14 样本替代。
- 备份可读、内置载荷更新、正常重启注册、四项人工通话和短信；新候选的换卡、号码显示和长期待机分别记录。
- 实际应用退出/重开任务、离线包及在线未发布/失败提示、BAR 同身份升级、载荷升级/回滚、分阶段完整恢复/卸载/重装。
- 新手机端与 r16 桌面互认及互斥；r14/r15 旧端对新载荷只拒绝写入。QNX 锁探针通过不能代替实际两端界面流程。
- 旧实验操作另验：每次启动重验 exact profile，停止须等待恢复；更新中断保留安装事务并拒绝盲重试；卸载只移除启动入口、不声称删除私有载荷。没有 legacy rollback；普通试测 PPS journal 不是自动原件导出回执，上次检查报告不能当实时状态。

旧 r7/r8 的九组语音与 r14 的 Q20/联通、Passport/移动短信证据继续有效，但只代表各自记录的版本和组合。没有新的 Q10、Classic 或其他硬件实机验收声明。

手机中历史试验留下的未知脚本或记录不能被当作发行自有文件删除。保留并核查它们；完整卸载因未知内容被拒绝是停止信号，不是放宽目录清理的理由。原厂未 Root 仍需电脑首次 Root，没有纯手机从零 Root 的承诺。
