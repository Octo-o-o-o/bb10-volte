# 原生手机候选验收记录

本文件区分代码/构建检查、安装入口、真实应用体验和无线能力。候选状态由本轮实测更新；旧 r7/r8 九组语音记录与 r14 两组短信记录保留为历史证据，不能代替新协议 2 的验收。

## 已取得的证据

- 固定 digest 的 BB10 工具链 doctor 通过；C++98/Qt4 原生 ARM32/QNX ELF 已编译链接。
- 候选 `0.1.0.1` 的完整 BAR、bootstrap ZIP、签名运行组件 ZIP 已构建；BAR 组件与签名清单逐字节回读一致。
- Passport `SQW100-4`、OS `10.3.3.3216`、AutoRoot v4：设备 Python `3.2.2` 可运行，`fcntl.lockf` 可用；从 UID 1000 经现有 `/bin/__root` 的 stdin 入口得到 UID 0。
- 同一手机的本机 AutoRoot installer 安装 bootstrap 包，收到 SUD 最终 success，并确认原生应用注册目录。
- 使用与 native 相同的私有字节副本桥实际调用签名 `inspect` 成功，返回当前设备、移动 SIM 和 IMS 状态，未改动原有无线服务。该证据只证明 Root 入口和只读运行链，未证明真实 app 沙箱操作。
- 两位独立 reviewer 已交叉复现并推动修复：停用/启用跨重启任务、备份失败继续、卸载后重装、钩子原子写中断、正常运行文件卸载认领、旧实验电信回执迁移、Python 3.2 ZIP 资源边界。最终复评与全套测试数字在交付时更新。

首次原生启动已到达系统应用权限对话框；系统日志同时显示启动被降为后台（可能为密码锁/通话/OOBE等系统条件）。尚不能据此声称 UI 已加载。不会修改安全设置、伪造授权或绕过密码锁来使记录变绿。

## 可发布结论规则

代码与构建通过可以形成候选包；人工无线与 UI 检查未完成时，只能标为待验收候选。发布文案必须逐设备、运营商、Root 环境和版本记录结果，不能写“所有 BB10 已支持”。完整构建、最终哈希及公开/私有边界见[发布流程](MOBILE-RELEASE.md)。
