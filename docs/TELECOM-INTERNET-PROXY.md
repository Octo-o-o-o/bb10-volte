# 电信 CTNET 浏览器代理修复

2026-11-03，Passport SQW100-4、OS 10.3.3.3216、电信 460-11 的现场显示：普通数据 APN 为 `ctnet`，LTE、数据连接及 IMS 均在线。手机直接访问 HTTP 测试地址成功；系统公布的 `10.0.0.200:80` 代理拒绝连接，浏览器无法打开网页。清除本次连接的代理状态后，机主确认浏览器可以打开网页。

手机选用的原厂 `/etc/carrier/config/446.xml`，SHA-256 为 `d94f9b7eaa664a9ac496475e706bb837c364635400dd1af9a79608337d57f407`。该文件将此代理写入普通 `ctnet` 的 internet 配置。自动适配原本保留原厂普通数据配置，因此在生成的运营商 XML 中也保留了该代理。

共用载荷对 `460-11`、上述原厂路径及哈希的组合，生成 IMS 运营商配置副本时，只移除 `ctnet` internet 条目的这个代理字段。原厂文件、普通 APN、IMS、彩信与其他字段均不修改。已知文件的结构不符合预期时停止；其他运营商、MNC、配置文件、哈希或代理保持原样。

离线检查中，原厂移动 `cmnet`、联通 `3gnet` 的普通 internet 条目没有这一代理；对应 `cmwap`、`3gwap` 条目中单独设置的代理保留。三款支持机型与三家运营商均经过共用配置逻辑的自动测试；这不等同于九组设备和 SIM 的新实机验收。其他地区、卡类型及不同哈希的运营商文件仍须单独验证。

随后按既有停用、重启、更新和启用流程安装了新载荷。Passport 再次重启后，只读核验原厂配置保持原样，生成的 CTNET 项和系统代理均已清除该代理；机主在关闭 Wi-Fi 的条件下确认 HTTP、HTTPS 网页、通话和短信正常。待整合载荷的 18 个文件与这次 Passport 更新回执一致。此结果限于 Passport／电信，不能代替其他机型的验收。

重刷后的 Q10／电信使用 v18/r18 时也出现 4G 浏览失败；其原厂配置哈希、运行时 CTNET 配置和系统代理与上述故障一致。Q10 尚未安装该修复载荷，需按正常更新流程重启后再实测网页、通话和短信。不要手工改写正在运行的载荷或它的恢复日志。
