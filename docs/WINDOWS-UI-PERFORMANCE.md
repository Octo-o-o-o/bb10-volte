# Windows 界面卡顿修复（2026-11-09，纳入 r43）

Windows r42 存在无需连接手机即可复现的界面绘制停顿。打开连接页、切换首次 Root 页、拖动或缩放窗口时尤其明显。

## 原因与修复

`tools/ui_theme.py` 使用小型半透明 PNG 为按钮、输入框、标签页、滚动条和进度条绘制圆角。Tk 的图像元素会平铺中间区域，而不是一次拉伸；原图中间区域只有约 2 像素。宽控件一次重绘产生大量 Windows GDI 操作，阻塞同一个 UI 事件循环。后台线程并不能避免这种原生绘制阻塞。

Windows 现改用 Tk 自带 `clam` 元素直接绘制，保留配色、布局、焦点、禁用状态与操作流程。其他窗口系统保留原圆角主题。进度动画由每 12 毫秒一帧改为 Tk 默认每 50 毫秒一帧，减少无意义重绘。身份、固件、Root、备份及刷写检查均未因性能修复而放宽。

原理与 [Tk 9.0 图像元素文档](https://www.tcl-lang.org/man/tcl9.0/TkCmd/ttk_image.html)一致。上游 [TIP 754](https://core.tcl-lang.org/tips/doc/trunk/tip/754.md) 也记录了 Windows 平铺图像的 GDI 成本；该提案状态为 Withdrawn，本修复没有假设上游已解决，也未更换或降级运行时。

## 本机对照结果

Windows、Python 3.14.9、Tk 9.0.4；相同电脑、相同源码和正常不透明窗口，唯一主题变量为上述修复。没有连接手机或运行下载。每 10 毫秒记录一次事件循环心跳；数字为最长心跳间隔，包含系统调度和绘制时间。

| 场景 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 主窗口首次绘制 | 873 ms | 43 ms |
| 主窗口持续缩放 | 644 ms | 23 ms |
| 连接页首次绘制 | 3693 ms | 58 ms |
| 连接页持续缩放 | 1366 ms | 18 ms |
| 首次 Root 页绘制 | 1800 ms | 50 ms |
| 首次 Root 页持续缩放 | 1082 ms | 29 ms |

这是本机短时复现，不是所有电脑的性能保证；初次绘制的 CPU 时间不等于稳定空闲功耗。未重新验证手机通话，不推断手机端或电池续航有变化。

## 防止回归

- `tests/test_ui_responsiveness.py` 在 Windows 实际映射窗口，覆盖三种 Tk 缩放比例、大输入框、按钮、标签切换、滚动条和进度动画。修复前的主题在三个比例均失败，修复后通过。
- `tests/test_scrolled_page.py` 保留滚动范围、滚轮、滚动条滑块和进度填充检查，兼容内置元素的名称。
- EXE `--self-test <报告.json>` 增加主窗口缩放、连接页和 Root 标签切换的心跳测量；测量不会连接手机。仅创建隐藏窗口而不实际绘制的旧自检不能捕获此问题。

本轮主工作区全量测试共 1100 项：1032 通过、65 跳过、3 项已有问题失败，分别为两项后续网站精简文案与旧断言不一致，以及未跟踪的录像说明含本地路径。桌面相关测试通过；没有为通过检查覆盖这些独立编辑。试用包从明确清单冻结源码构建，排除三份无关的未跟踪录像目录，另做包内校验和离线 EXE 自检。r42 原发行文件保持不变。
