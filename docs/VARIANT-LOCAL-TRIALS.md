## 用户操作

SQW100-3 只执行检查和导出反馈，跳过下列 4–7 步；不要安装、启动或执行停用恢复。可直接转发的 Passport 说明已按只读流程单独编写。

1. 使用 r15 的 Windows EXE 或 macOS DMG，并核对随包 SHA-256。r15 包含候选入口，但不代表新增机型已验收。整个试测使用同一个包；手机已有正在运行的三网自动服务或手机版事务时，先保留现状，不能用实验入口覆盖。
2. 从“更多 → 候选机型本地试测”进入，选择手机“设置 → 关于”中的完整后缀和实际运营商，点击“检查本机条件”。正式界面也可从“更多 → 候选机型本地试测”进入。首次检查不会自动勾选实验同意，也不会安装、刷机或重启。
3. 没通过时，按具体项目处理；通过“更多 → 导出检查报告”保存 JSON。未知文件版本、错误后缀、缺少 LTE 数据、SIM 不匹配或恢复未验证，不能靠反复点击或修改配置跳过。
4. 手动候选通过技术检查后，用户明确勾选实验试用并重新检查，再确认已有备份、SIM 已开通 VoLTE且无通话。点击“安装并验证”只安装，不自动启动。此路径不修改基带入网策略；电信手机必须已经有正常 LTE 数据。
5. 安装回读完成后再单独点击“启动并验证”。使用手机系统拨号器自行测试呼入、呼出、双向声音和全程 LTE。注册成功只能作为开始通话测试的条件，不能当作通话验收。
6. 测试短短信、长短信、两条内容相同但分别发送的短信和短信发送；观察后续是否重复投递。无需在反馈中提供短信内容或对方号码。
7. 点击“更多 → 停用并恢复”，等待恢复核对完成。再正常重启，确认没有自动启动。重启后若要继续试用，选择相同候选、重新检查并手动启动；不要热插拔换卡。停止/恢复未通过时保留报告，不重复安装。
8. 通过“遇到问题 / 反馈”保存反馈 ZIP，并附上脱敏检查报告及试测结果表。未做的项目填“未测试”，不能由 IMS 注册或程序退出码代填成功。

如果 SSH 连接失败，仍需电脑系统、试测包文件名和具体连接错误。手机版就绪后可复用相同试测条件省去此传输步骤；本工具不安装手机版，也不重复实现手机安装事务。

## 本地材料与源码入口

候选窗口的“导出试测配置与结果表”会在所选目录创建新子目录，包含 19 个绑定型号的配置、42 格范围表和空白结果表，不连接手机，不覆盖旧目录。

源码环境可执行：

```sh
python tools/gui.py --variant-trials
python tools/gui.py --trial-variant SQC100-3 --trial-operator unicom
python tools/variant_trials.py --export /path/to/new-trial-folder
```

r15 的 Windows EXE 和 Mac 通用 DMG 均包含试测入口及 Python/Tk。旧 r14 包不包含此入口；本轮没有新增后缀的真机验收。

## 与手机版合并

- 复用 `tools/variant_trials.py` 产生的配置和 `device/profiles.py` 保留前缀 `variant-trial-` 的解析与验证；手机不应直接导入依赖桌面路径/翻译的工具模块。
- 手机的 legacy inspect/install/start 使用同一 `device/compatibility.py`，因此型号绑定、六个散列、手动策略和 Passport 恢复限制都在设备端重新检查。
- 手机报告输出的字段允许集需加入 `variant_trial`，以保留经过校验的未知板型、六个散列和试测目标。该字段不是安装许可，也不是实机通过记录。
- 配置中自启动固定 false。安装后不连带 start；手机界面也应把两步分开。不能让 UI 把“候选可检查”显示成“已支持”。
- 本分支更新固定允许替换集合时只增加 `profiles.py` 与 `compatibility.py` 两个已审查 Python 文件，原生二进制仍不允许替换。与手机版事务合并后重新生成两份载荷清单并回归 r14 迁移、半安装和恢复。

自动服务白名单、原生补丁及额外 Passport 后缀的恢复路径没有被放宽。新后缀是否正式支持，需要据收到的真实报告和通话/SMS/恢复记录再逐项决定。
