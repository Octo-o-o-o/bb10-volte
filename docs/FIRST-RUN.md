# 首次使用与连接准备

当前开发源码从“连接手机 / 连接帮助”进入，SSH 文件路径移至高级设置。已发布 r6 及更早应用仍使用下文部分旧入口名称；本次新流程尚未发版。重新打开时会复查上次成功连接，授权和已完成的镜像准备可以继续；完整场景见[连接流程](CONNECTION-FLOW.md)。

[English](FIRST-RUN.en.md) · [GUI](GUI.md)

桌面修订 `0.3.2-r6` 的“首次使用”向导负责连接检查、Windows 连接组件、USB 驱动和 Q10 初次 Root。主界面的日常检查与通话服务安装不需要重复下载这些材料。

## Mac 首次连接

Mac 用户先看[手机连接指南](MACOS.md)：未 Root 的 Q10 可了解r6 macOS 14+ 的实验原生准备与确认后分阶段执行（未实机首刷，旧 r5 DMG 不含新集成）；已 Root 且有个人配置可导入或直接检查；已 Root 但无任何旧 Windows 文件，可由这台 Mac 生成独立密钥，在手机已有有效 Root 终端中明确授权。无材料且无有效 Root 终端时不能直接连接。新授权会持久追加手机 SSH 公钥，须本人决定后输入 `PAIR`；不会把开发模式当作 Root。

新 Mac 与手机可用 microSD 读卡器和手机文件管理器传递公开脚本及结果，不假定 Finder 能挂载内部存储，不需要旧 Link；具体来回步骤和未测试范围见[连接恢复](RECOVER-CONNECTION.md#mac-没有旧文件时如何传递授权脚本与结果)。

已发布 `0.3.2-r5` 的主界面已通过 Mac 日常连接验收，但首次向导有 Root 诊断误报和 USB 信息不足；仓库源码修复不代表旧 DMG 已更新，见[Mac 验收记录](../materials/macos-device-validation-2026-10-28.json)。

## 已经 Root 或已启用 VoLTE

已有 Root 但没有连接文件时，可点击“恢复连接”：用现有私钥补建配置，或通过手机已有 Root 终端授权本电脑。Windows 和 Mac 共用此流程，见[连接恢复指南](RECOVER-CONNECTION.md)。

连接并解锁手机，点击“检查设备”。应用会查找本机保存的连接、个人 Root 工作目录、便携程序旁的配置以及明确的 `bb10-root` / `q10-root` 别名；不会递归搜索磁盘或使用共用私钥。未保存的自动连接仅限直接 USB 地址，并保留主机密钥校验。自定义地址请主动导入自己的配置。

旧配置只定义 `q10-root` 时会自动匹配。连接成功后仅保存配置路径和别名，私钥留在原目录。已安装服务会读取当前状态：注册与 LTE 正常时显示已启用，启动中显示等待；运行中占用通话配置是预期状态，不会作为安装失败。

**连接配置可以留空。** 点击“检查设备”会检查个人目录中的 `root-kit/ssh_config` 与 `root-kit-*/ssh_config`，验证与手机的连接后自动填写；下次打开会恢复上次成功的配置。首次向导在“自动准备 Root 镜像”时生成这些文件，完成刷写并验证 Root 后自动带回主界面。即使在保存连接前关闭了程序，下次检查仍能查找带编号的工作目录。有多套文件时按实际连接验证选择，不能仅凭文件较新就认定匹配。没有对应密钥的已 Root 手机需导入原有个人材料，或在已有有效 Root 终端中授权本电脑。

USB、开发模式、SSH、Root 与 IMS 是不同层次。**开发模式关闭不表示 Root 失效；已有有效 Root SSH 时无需一直开启开发模式。** 程序通过匿名 USB 发现信息读取型号、系统与开发模式标志，通过正常 SSH 验证访问；不会建立后立即丢弃开发服务会话。

如果手机刚重启，请等待 Root 和 IMS 先后启动，再重新检查。已有 AutoRoot 可打开一次 BlackBerry World 触发本地启动；商店“无网络连接”或持续加载不等于 Root 失败。SSH 仍拒绝时，可从手机电源菜单正常重启后再等 Root。密钥不匹配应导入原有配置，不能关闭校验或据此重复刷写。

## Mac 实验首次准备与执行

r6可在 macOS 14+ 的“首次使用 → 首次 Root”准备 Q10 个人材料及镜像，应用按架构获取并校验原生 bb10mt/7-Zip、私有 libusb/LZO，不需要安装 Homebrew。准备本身不接触 BootROM，不刷机；保留 AppWorld，并核对原版分区散列。刷写须再次核对唯一手机、具体变体、`169.254.0.2` USB 地址及备份；Mac 另须勾选“已核对手机尚未 Root，理解 Mac 首刷尚未实机验收”，单独确认清空后才打开 Terminal 按阶段执行。

未 Root 的 Passport（Q30）或 Q20 当前缺少已集成的匹配首刷材料；先核对具体 `SQW100-*` / `SQC100-*` 变体，再接入对应固件、loader 与方法。不能选 Q10 变体、修改配置或勾选实验试用来套用 Q10 镜像。已 Root 的 Q30 VoLTE 实验识别与初次 Root 是两条不同流程。

Mac 任何原生错误、缺少完成证据、取消或未知状态都暂停并保留现场，不重试、不自动续 radio；**Windows 的退出 73 例外不能用于 Mac**。r6尚未进行 Mac 实机首刷，旧 r5 不含新集成。完整条件及边界见[Mac 首次 Root](MACOS.md#mac-能否首次-root)。

## Windows 初次准备

1. 打开“首次使用”，检测手机与 USB 网络。驱动缺失时进入“Windows 驱动”，应用自动下载固定材料，核验 BlackBerry 安装包、MSI 和微软驱动目录签名；确认后通过正常 Windows UAC 安装。已就绪的驱动无需重复安装。
2. 按手机提示解锁；首次开发连接可在“设置 → 安全和隐私 → 开发模式”操作。应用会显示读取到的状态，不能远程代替手机上的必要确认。源码用户缺少 SSH 时，可点“准备连接组件”自动获取，不必另装 OpenSSH。
3. 未 Root 的 Q10 进入“首次 Root”，核对 `SQN100-1` 至 `SQN100-5` 的实际变体。准备至少 15 GB 可用空间并备份手机。
4. 点击“自动准备 Root 镜像”。应用自动获取 AutoRoot v4、固定 Q10 固件、libusb、LZO、便携 7-Zip 和 MinGit 内的固定 OpenSSL DLL；校验所有散列。无需用户另装 Git、7-Zip 或其他 Root 项目。每次生成独立个人密钥，并构建、校验同次生成的 OS / radio 镜像。**这一步不会刷写手机。**
5. 确认备份、机型及清空数据后，才可进入刷写。应用再次核对唯一 USB 手机的型号、镜像散列和 Root 状态；已验证 Root 或明确的密钥问题会阻止刷写。OS 与 radio 顺序运行。设备密码只在厂商刷写窗口输入，不通过应用命令参数传递。
6. 手机首次开机后完成必要设置，打开一次 BlackBerry World，回到“连接检查”验证有效 UID 0。然后返回主界面，重新检查并安装 VoLTE。Root 成功本身不证明运营商注册或通话通过。

未知退出、中断或与已记录流程不符的结果会暂停并保留状态，禁止盲目重试。对于此固定 AutoRoot 配方，只有 OS 已写到 100%、随后同时出现已记录的两条安全错误且退出码为 73，才按作者说明接续 radio；其他错误不忽略。源代码中的这条分类有回归测试。依据见 [AutoRoot v4](https://bb10.root.sx/blog/autoroot-v4) 与原有 Q10 刷写记录；最终仍需检查 radio、开机和 UID 0。

## 平台和验证边界

- Windows 与 Mac 实验首次 Root 均仅提供 Q10 固件配方；实际硬件记录仍仅 Q10 SQN100-3。Q20 / Passport 需要各自的固件，禁止复用 Q10 镜像。
- Mac 应用提供已 Root 手机的连接、状态、VoLTE 流程和手机操作提示；r6新增 macOS 14+ 原生首次准备和分阶段执行，尚未实机首刷，旧 r5 无此新集成，见[步骤与未验收范围](MACOS.md#mac-能否首次-root)。不能把双架构 DMG 的启动或镜像构建当作 Mac 首刷验收。
- 本轮已验证固定下载和便携工具校验、生成独立个人密钥、构建并核对两份 Root 镜像、驱动材料与签名校验，以及已 Root Q10 的连接与服务读取。自动刷写分支完成了模拟回归，**未在未 Root 手机上实刷，也没有重刷当前已启用手机**。新向导仍是实验功能。
- Root、驱动首次准备需要互联网或预先缓存的固定材料；程序没有在线激活、收费校验或 AI 运行依赖。原厂固件和个人密钥不会打进公开安装包。
