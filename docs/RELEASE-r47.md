# 桌面 r47 / 手机版 0.1.0.47：三网全号段 HPLMN 覆盖与原厂 XML 兜底＋Passport 电信呼入无声回归修复

2026-11-15。macOS 仍停在 **v0.5.0-r43**，本次没有新的 Mac 安装包。

- **修复新版移动／联通／电信号段卡提示“没有对应的模板”无法激活**：补齐三大运营商全量商用 USIM 归属 HPLMN 准入——中国移动 `460-00`／`02`／`04`／`07`／`08`、中国联通 `460-01`／`06`／`09`、中国电信 `460-03`／`05`／`11`／`12`，并将 APN 大小写不敏感匹配扩展至 `cmnet`／`cmwap`、`3gnet`／`wonet`／`uninet`、`ctnet`／`ctlte`。
- **原厂只读运营商 XML 哈希固定兜底与两阶段空 APN 引导**：BB10 `10.3.3.3216` 原厂运营商库早于 `460-08`（移动新发 5G USIM）、`460-09`、`460-12` 等号段，会将 `preloadedConfigFile` 指向空壳默认文件 `/etc/carrier/config/0.xml`（或留空），导致激活前既无内置运营商模板也无默认数据 APN。本次仅当无已下载 OTA 覆盖（`downloadedConfigFile` 为空）且 `0.xml` 与目标原厂只读文件（移动 `404.xml`、联通 `36.xml`、电信 `446.xml`）SHA-256 逐位匹配时，自动选用对应原厂模板生成受管 `carrier.xml`（电信四号段同步清除 `446.xml` 内失效 `10.0.0.200:80` 代理），并在 `cdsc_xml` 尚未接管前允许一次受控空 APN 引导；写入受管 `carrier.xml` 后恢复严格 LTE 数据就绪检查，原厂 `/etc/carrier/config/*.xml` 全程只读不改。
- **修复 r45／r46 引入的 Passport（Q30）中国电信呼入接通无声回归**：反汇编核实原厂 `ims_rrm` 的 `MediaDialog::populateBody`（`0xc621c`）在 `Omit200OkSdp=1`（原厂默认 `0xb8e9c = 0121`）时已有完整的 `SDPState` 状态机保护——仅当 `SDPState == 0xd`（已通过 `183 Session Progress`＋`PRACK` 或 `UPDATE` 完成前置条件媒体协商）时才在 `200 OK` 中省略重复 SDP；而无前置条件的 `180 Ringing` 路径（`SDPState != 0xd`）及被叫后发 Offer 路径仍正常在 `200 OK` 附带完整 SDP。r45／r46 强置 `Omit200OkSdp=0` 会使 `200 OK` 在电信 `183`＋`PRACK`／`UPDATE` 之后再次下发第二份 SDP Answer，在 Passport 电信数优策略路径上重触发媒体会话协商并导致接通无声。本次恢复原厂 `MediaDialog.Omit200OkSdp=1`，同时保留 `MediaDialog.EarlySdp=0`（`0xb8eb0: 0221 -> 0021`，消除 `180 Ringing` 重复或预览 SDP），已在 Unicorn 机器码仿真中覆盖全部 12 个号段与各呼叫状态分支。
- **明确区分不支持的 SIM 原因与增强脱敏媒体诊断**：桌面端、手机原生应用和 AI Skill 现分别提示中国广电 `460-15`（BB10 硬件无 700 MHz Band 28 且不在三大运营商范围）、含 ISIM 应用的新版 5G USIM、系统存在已下载 OTA 运营商配置覆盖，以及带脱敏 `MCC-MNC` 的未知归属网络；同时扩展脱敏诊断中的 `MediaDialog`／`SDPState`／`RTPMediaSession`／`AudioMediaSession` 媒体标记并过滤 SIP/tel URI、Call-ID、IP 与用户标识，保留 `vpn_login` 会话 UUID 校验。电信出站短信本地完成补丁（`telecom_mo_ack`）与状态栏黑莓图标自动点亮同步覆盖全部电信四号段（`03`／`05`／`11`／`12`）。
- 已发布的 r42／r43／r44／r45／r46 后台停用后可直接原地升级，保留原备份和恢复机制。离线仿真与单元测试不替代外省及各后缀真机双向语音和短信实测；各型号历史记录仍按原测试版本单列。Windows EXE 仍没有 Authenticode 发布者签名。
