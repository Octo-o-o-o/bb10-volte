## 设备到达后的顺序

1. 逐台登记收机状态，查看设备外观、开机与基础功能，从手机系统读取完整型号、OS / radio 和可读取的板型；把实测结果写入该型号自己的记录。型号不符时停下来核对，不能沿用包裹标签、家族名字或固件文件名。
2. 确认机主已经备份并允许清空，记录现有系统、Root、SIM、可用 LTE 数据和其他已有适配工具；保留原始备份。只读探测无法读取的字段保持未知，不能猜测。
3. 如确需升级或 Root，使用与实际后缀匹配的 10.3.3.3216 固件、原始材料、加载器和目标机器单独生成的密钥；核对 BootROM ID、完整加载器来源及哈希，并分别记录 OS / radio 写入和开机回读。配方存在不代表该型号或主机平台已完成首刷验收；不确定加载器时停止，不能套用其他后缀或绕过校验。
4. 再读取本型号的六个原生文件指纹、QNX/Root 状态、板型、SIM 类型、归属 PLMN、原厂运营商模板、LTE 数据和已有服务状态。实际散列与已知版本不一致时分析差异，不能简单添加新散列放行。
5. Q10 / Classic 的手动候选须通过全部检查，安装和启动分别执行，初始不启用自动启动；SQW100-1 保持只读，直到其停止、恢复和重启生命周期有独立证据及相应实现。
6. 对每个可测运营商分别记录桌面与手机版的实际版本和结果：安装、启停、IMS、呼入／呼出、双向声音、通话期间 LTE、通话后数据、短短信、长短信、重复内容短信、恢复及正常重启。未执行填未知；不以注册成功代替通话结果，不以一张卡或一个客户端的结果推定其他组合。

## 今后桌面版与手机版如何保持对应

- `materials/device-support.json` 记录研究目录与频段候选；桌面 `tools/device_support.py`、`tools/variant_trials.py` 按**完整型号 + 运营商**给出范围。目录条目、Root 配方和候选配置都不能单独授权自动服务。
- 自动服务的型号、板型、系统和 SIM 限制由共享手机端 `device/carrier_policy.py`、`device/unified_install.py` 等执行。当前自动名单只有 SQN100-3、SQC100-2、SQW100-4。新增型号必须先有该型号、实际板型及相应运营商的证据，再审查代码和恢复路径；不能按 Q10/Q20/Passport 家族直接放行。
- 手机候选目录由 `tools/package_mobile.py` 从桌面候选计划生成；`mobile/native/assets/Experimental.qml` 的可见选项仍单独维护，`mobile/runtime/worker.py` 与 `device/compatibility.py` 再核对真实型号和权限。`tests/test_mobile_trials.py` 检查目录与执行限制，`tests/test_variant_ui_labels.py` 检查每个可见型号、运营商、只读标记和选中值与生成目录一致。
- 现有旧版迁移 `device/unified_migrate.py` 只认识三个历史型号；为新型号开放自动流程之前，应按该机实测处理干净安装与已有旧组件，不能猜测旧目录或直接复用其他型号的备份。手机端旧手动配置还有单独的历史型号限制，也不能因自动名单变化而盲目放宽。
- 适配完成后按型号、OS、运营商、SIM、桌面版本与手机版本分别登记实际证据，再同步支持目录、官网状态表、界面、发行说明和打包清单，运行跨端一致性与恢复回归。桌面应用和手机 BAR／载荷要分别构建、核对与验收；源码测试通过不等于发行包或真机通过。

现有三个型号的历史语音实测也不等于当前所有版本的完整验收；特别是 r21 / 手机版 0.1.0.19 尚未完成 Q10 整包实机验收。以当前 [README](../README.md) 与对应版本的证据为准。
