# 拒接后来电界面反复出现：离线核查记录

2026-11-17 收到的描述是：来电后第一次挂断，来电界面反复出现，随后接听、挂断均无效，重启才恢复。没有对应的完整型号、运营商、应用版本、按键方式或现场日志。本记录验证已提出的两项原生代码假设；**尚未复现该故障，根因与修复状态仍为未知**。

核查基线为产品 `v0.5.0-r48` 的 IMS 构建逻辑及本地原厂 10.3.3.3216 映像。不能由此推断反馈者使用 r48，也不能排除其他版本、网络事件、进程退出或界面状态导致相同症状。本次未修改运行时二进制补丁、版本号或发行附件，未连接测试手机。

## 已核实的两条路径

1. **正常来电不会因状态谓词而跳过拒接。** `ims_rrm` 的状态名称跳表 `0x16b3aa` 返回 `-1=null`、`0=early`、`1=completed`、`2=confirmed`、`3=cancelling`、`4=terminated`。`0x16b30a` 判断的是 `early`。来电构造调用点传入方向 `1` 和初始状态 `0`，外呼才传入初始状态 `-1`。执行 `MediaDialog::reject` 的原生指令后，来电 early 状态在已覆盖的 SDP 状态下会到达 UA 拒接调用，并传递 486／603。原先把 null 和 early 对调而提出的谓词补丁没有依据。
2. **跳过详细原因通知不等于丢失结束状态通知。** 在注入派生 busy 状态 `2`、无遗留 busy call ID 的夹具中，来电或已移除 dialog 会经过 `0xd4af6` 跳转；后段仍经 `0xd5276` 调用 `0xcc2c4`，请求发送 `0xa01` 消息，其中 `0xa02` 是模拟 call ID，`0xa03=0` 是结束状态。外呼 busy 则保留另一条 `0xa03` 详细原因通知和延后断开路径。原先只检查前段分支而提出的强制跳转补丁没有依据。

这些结论针对上述路径和前置状态。第二项测试从已派生状态的处理尾段开始，未验证真实 SIP 响应如何生成状态，也未证明 qct、蜂窝服务和来电界面一定收到并正确处理通知。

## 可重复验证

[原生回归测试](../tests/test_call_rejection.py)覆盖状态名称、来电构造参数、486／603 拒接、结束态保护、来电 busy／缺失 dialog 的后段通知以及外呼 busy 路径。测试对原厂、当前通用 IMS 和电信 IMS 构建执行四个加载基址，并用仅存在于仿真内的错误谓词作反向对照。

需要本地合法取得的固定原厂 `ims_rrm` 与可选依赖 Unicorn。可通过环境变量 `BB10_STOCK_IMS_RRM` 指定映像；缺少映像或 Unicorn 时原生测试会跳过，不能把跳过视为通过。仓库不包含原厂映像。

```text
python -m unittest discover -s tests -p "test_call_rejection*.py" -v
python -m unittest discover -s tests -p "test_mt_call_signaling.py" -v
```

固定原厂 IMS SHA-256 为 `043d38b0f08cf6a9696ef405f3976679e32ff9ad943ec35294c3d3da69a12b67`。核查日志字串时所用 qct 映像 SHA-256 为 `71835f701affcb9254eadb4ee299e8f7d07547543b3e0f61519456b8241dcb3b`。

仿真执行真实 ARM 分支，但以夹具替代 C++ 所有权、日志、互斥量、dialog 查询、TLV 序列化和传输接口。它没有启动 QNX 进程或完成运营商通话，不能作为声音、拒接界面或实机稳定性验收。

## 现有日志的脱敏分析

[离线分析工具](../tools/analyze_call_rejection.py)只处理已有文本，输出固定事件计数、有效 SIP 状态码和证据限制。它不会连接手机，也不会输出原始行、号码、呼叫标识、设备标识或本地路径。原始日志应保留在私有目录。

```text
python tools/analyze_call_rejection.py --input private/call.log --output private/call-summary.json
```

工具拒绝覆盖输入及已有输出，最多读取 8 Mi 个字符、100000 行，每行最多 16384 个字符；触及限制会标记 `input.truncated=true`。`root_cause` 始终为 `not_determined`，`call_acceptance` 始终为 `not_assessed`。不同呼叫的事件未关联，日志可能不完整，缺少某条事件不代表该事件没有发生；计数和状态码不证明现场日志真实性或修复有效。

后续若取得可复现条件或故障时日志，应沿拒接命令、IMS 拒接返回、结束回调、qct 断开通知和界面清理逐段定位。当前不应应用上述两项未经证实的二进制补丁，也不应将本记录写入型号／运营商已通过验收结果。
