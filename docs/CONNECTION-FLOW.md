# 连接手机：使用场景与实现方案

本方案适用于 Windows 和 Mac 共用桌面界面。普通用户从“连接手机”开始；SSH 配置路径和别名位于“更多 → 高级连接设置”。手机端协议、权限和身份校验保持原有约束。

## 判断依据

应用使用历史与手机状态分开处理。首次打开应用不意味着手机未 Root；关闭重开不意味着手机仍在线。USB 识别、网络可达、手机身份、登录授权、有效 Root、VoLTE 安装与注册分别取证。未验证的状态显示“待确认”，不会从连接失败推断“未 Root”。

只有实际有效 Root 检查通过，才保存成功连接。打开应用时仅对上次成功连接进行一次重新检查，不自动安装、启停服务、下载、授权或刷写；失败后保留记录，由用户重试或恢复。

## 场景与下一步

| 场景 | 应用表现 | 用户下一步 |
| --- | --- | --- |
| 第一次使用，不清楚是否 Root | 首页显示连接手机；打开统一连接检查 | 接线、解锁，点击连接 |
| 第一次使用，已有本机连接材料 | 查找应用个人目录与原有已知位置，验证后选用 | 验证成功后继续 VoLTE 检查 |
| 关闭后重开，曾成功连接 | 自动复查一次；此前结果不能提前解锁安装按钮 | 已连接则继续，未连接则处理具体原因 |
| 重新打开时手机未接入或尚在启动 | 保留已有连接，提示重试与连接帮助 | 接入手机或等待启动后重试 |
| 原配置被移动或删除 | 保留原引用，明确提示材料不可用 | 选择原文件夹，或从手机重新授权 |
| 已 Root，只有以前刷机的文件夹 | 识别常见登录私钥与手机身份记录 | 确认材料来源后验证 |
| Windows 材料迁移到 Mac，或反向迁移 | 根据可用密钥和身份记录重建当前电脑路径 | 选择材料文件夹，无需编辑旧路径 |
| 找到多组不同材料 | 不按修改时间或目录顺序猜选 | 选择当前手机对应的子文件夹 |
| 只有私钥，缺少可信手机身份 | 明确显示缺项 | 补齐原可信记录，或从手机重新授权 |
| 已 Root，没有任何旧材料 | 先解释手机端授权条件 | 有有效 Root 终端时进入三步授权 |
| 无材料，也没有有效 Root 终端 | 说明无法直接建立授权 | 取回原材料或通过原 Root 工具恢复访问 |
| 手机授权中途关闭应用 | 保留本机密钥、请求编号及已确认步骤 | 继续原请求；多条请求按编号选择 |
| 手机已生成结果，但电脑应用已重开 | 可直接导入同编号结果，核对本机密钥 | 确认来源并验证连接 |
| 用户确认手机尚未 Root | 独立打开首次准备；实际刷写仍需完整确认 | 核对支持机型并备份，再按向导准备 |
| Root 镜像已准备，应用关闭后重开 | 列出准备记录；选定后重新核验镜像 | 重新确认备份等条件；不自动刷写 |
| 刷写完成，等待首次启动 | 恢复该准备记录后转到连接检查 | 完成手机设置、启动 Root，再验证 |
| 刷写中断或结果不确定 | 保留日志和锁，不提供自动重复刷写 | 先核对现场与刷写记录 |
| 密钥被手机拒绝 | 说明当前电脑授权不被接受 | 原材料导入或手机重新授权 |
| 手机身份与记录不同 | 保留原身份记录，明确要求核对 | 确认换机/重刷，提供新的可信来源 |
| 换手机或本机有多套历史连接 | 可明确选择重新查找本机连接 | 只连接目标手机，再验证匹配材料 |
| 同时接入多台黑莓 | 统一检查入口在认证前停止 | 只保留当前手机 |
| 已连接但有效 Root 不可用 | 显示 Root 待确认，不判定为未 Root | 通过原工具恢复有效 Root 后重试 |
| VoLTE 已安装或正在启动 | 继续使用原有预检与服务状态逻辑 | 查看状态、等待注册或执行已允许的操作 |
| 拔线后重新接入，或换卡 | 主界面显示最近检查快照，不承诺实时在线 | 重新检查，设备操作仍受原有预检与确认约束 |

## 文件夹识别与本机保存

扫描仅限用户主动选择的目录，最多检查 2,000 个目录项、6 层子目录。跳过符号链接、目录联接、版本库和依赖目录，不执行发现的 SSH 配置，不扫描全盘。原文件夹中的 Windows/Mac 绝对路径不会直接复用。

支持常见 RSA 登录密钥名称、PEM/key 格式候选，以及手机 RSA 主机公钥或含直接 USB 地址记录的 known_hosts。只找到唯一一组材料后才提供确认与验证；同内容的备份可去重，多组、缺项、无法读取或超出范围均要求处理后再继续。手机主机私钥不能当作电脑登录私钥。

确认来源后，按原恢复机制复制登录材料到受保护的应用个人目录，生成本机配置，再严格校验手机身份与有效 Root。只有成功才记住连接。原文件不移动、不覆盖。高级手动 SSH 配置保留原位置和自定义行为，不擅自搬移依赖文件。

真实刷机目录可能同时包含密钥和大量构建文件。遇到扫描上限、多组材料或无法读取的子目录时，用户可明确选择“只检查当前文件夹”，重新仅扫描该目录的文件，界面显示检查范围。不会自动将部分扫描结果作为完整材料接受；本层仍须满足唯一登录密钥、唯一可信手机身份和数量限制。用户无需搬动原有资料。

## 授权与恢复进度

三步分别是“把授权文件放到手机”“在手机上允许这台电脑连接”“取回手机授权结果”。步骤进度只表示用户已完成的操作，不等同于权限或连接验证成功。关闭应用不删除待配对密钥；重开使用原编号与密钥，不自动生成替代请求。多个未完成请求必须按手机文件编号选择。验证成功后标记本次请求完成。

电脑私钥留在电脑。手机脚本核验有效 Root 和支持的授权布局，输入 PAIR 后才追加授权；START 仍是单独选择。结果必须匹配原电脑请求，既有手机身份不同则拒绝覆盖。现有手机脚本没有在所有第三方一键 Root 包上实机验证，界面简化不扩大兼容性承诺。

## 验证范围

实现使用共用 Tk 界面和 Python 逻辑。场景回归覆盖首次/重开、丢失配置、材料歧义、部分扫描、权限未验证、授权恢复、多设备阻断、刷写状态不确定和最小窗口布局。测试模拟设备响应；通过测试不代表本轮完成手机重新授权或 Mac 实机验收。首次 Root 仍以原平台说明和刷写保护为准。
