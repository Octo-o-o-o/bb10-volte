BB10 VoLTE — on-phone bootstrap / 手机端首次安装
Target application version / 目标应用版本：VERSION

For an already rooted, compatible AutoRoot v4 phone with a working local Root
terminal and its existing installer. This does not root a stock phone. Stock
phones still need the desktop first-Root workflow. Other Root methods require
their own validation.

从可信的同次候选交付或项目正式 HTTPS Release 获取文件，核对公布的完整 SHA-256。
包内公钥不能自行证明首次下载的来源；正式发布后请核对官网同版校验信息。
已有 BARinstaller：使用同版 BAR。只有 Root 终端：把本 ZIP 保存到 Downloads，
确认实际文件名与下方命令完全相同，然后在原有 Root 终端执行：

/var/rootdata/installer /accounts/1000/shared/downloads/bb10-volte-VERSION-bootstrap.zip

构建会替换命令与标题中的版本占位符；若文件名或目标版本不匹配，先停止核对。
不要将其他版本的脚本、BAR 与引导 ZIP 混用。

安装通过必须同时具备：
1. 对应同一安装任务的 SUD 最终 success。
2. 实际应用注册版本与本页目标版本一致；打开后也核对界面应用版本。

实测 AutoRoot installer 在 120 秒超时后仍可能打印 completed。曾经 v2 安装无
SUD success，实际仍是 v1 注册版本，因此 completed、旧图标或旧版能打开都不是
升级成功证据。超时保留输入并查询同一任务，不反复提交安装。

正常解锁并自行确认首次系统安装/应用权限。到达权限对话框不代表界面已经加载。
每次重启后，先等系统出现 Root 成功提示，再打开应用一次。Root 尚未生效时，
系统可能直接拒绝启动本应用，应用内等待页此时也无法运行。若图标没有反应，
不要连续点击；本机已观察到反复启动被拒绝后系统桌面卡住。
首次进入请点检查；以后打开显示标明“上次检查”的结果，需要当前状态时手动检查。
应用会再核验签名载荷和手机条件。若已有 waiting_reboot 任务，先检查原任务；旧多阶段任务缺少安全保护时会要求保留现场并导出诊断；
旧服务停用、恢复并重启后，用应用的内置更新入口接管，不另选同版本更新 ZIP。
真正未安装服务的手机才从备份开始激活。按提示正常重启后，自己验证呼出、呼入、
双方声音和 LTE。安装应用与激活服务、验证通话是不同步骤。

上述原件备份和完整恢复指自动协议 2。高级页的旧实验路线范围不同：普通试测
以启动时 PPS journal 恢复，不冒充自动原件导出回执；实验卸载只移除启动入口、
保留私有载荷和备份，没有新增实验回滚。只读 Passport 试测不提供写操作。

Obtain the archive from the same trusted candidate delivery or an official HTTPS website or Release.
Verify its complete published SHA-256 before running it; the bundled public key
does not authenticate a first download by itself. Use the version-specific
command above only when its filename matches the actual download.

Installation passes only when the SAME job has final SUD success AND the actual
registered application version matches the target at the top. Check the native
app version after opening it too. An observed installer printed completed after
a 120-second timeout while the registered app remained the previous version.
A completion message, old icon or working old app is insufficient. Keep the
input and query that same job rather than resubmitting an unknown result.

Unlock normally and personally accept the system's installation and first-use
permission prompts. A permission dialog does not establish a loaded app UI.
After every restart, wait for the system Root success notification, then open
the app once. Before Root is ready, the OS may reject the app before its waiting
page can run. Do not repeatedly tap an unresponsive icon: repeated rejected
launches have been observed to freeze the system home screen on this phone.
On the first launch, tap Check. Later launches show the labelled last result;
check manually when current status is needed. Check an existing waiting_reboot
task before another change. An older multi-stage task without current safety
protections is retained for diagnostics instead of automatically resumed. After
an old service is stopped, restored and normally restarted, use the app's
bundled-update action; the same-version ZIP is not that adoption path.
Installation, activation and real call acceptance are separate steps.

Original-file export and full restoration above refer to automatic protocol 2.
Ordinary legacy trials restore from their startup PPS journal, not a protocol-2
original export receipt. Experimental uninstall removes startup entries only,
retaining private payloads/backups; no legacy rollback is added. Read-only
Passport trials never authorize writes.

No installer and no effective Root terminal: restore the original local entry,
or use the desktop setup once. A browser cannot grant missing privileges.
AutoRoot v2/v3 require separate validation; do not assume the v4 command applies.
Use desktop r21 for this protocol-2 payload. Old r14, r15, r16, r17 and r18 adoption requires
stop/restore and a normal restart first; never run old and new writers together.

Runtime ZIP updates do not replace the C++/QML app BAR. Internal backup copies
remain on this phone; keep an SD-card or other independent copy when available.
Keep original backups private. Removing the app icon alone does not restore or
remove the service; finish the app's restoration workflow and restart checks.
